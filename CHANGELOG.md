# What's new in omp-agents

Each update to omp-agents adds a few lines here, newest first, in everyday words.
The dashboard shows the same lines in Settings › What's new.

## 2026-11-26

- Bots are gone. Each routine now belongs to one Workspace, and every run posts a Board task there, so a fresh session does the work on its own branch and you can merge it from the Board.
- A routine whose last Board task is still open replies on it instead of posting a new one.
- A run that finds nothing to report closes its Board task quietly, without a notification.
- Each Workspace on the Board has a Routines tab, in place of the Bots tab, where you make and edit its routines and pick their model.
- Your Bots' routines moved to their Workspaces, each carrying its Bot's job and memory in its prompt. The Bots gallery, Bot designer, PR shepherd, and Bot messages are removed.
- Any session can now create and edit the routines of its own Workspace.
- On Pull requests, a pull request whose only failing checks wait on someone's approval, such as a workflow GitHub holds for approval or a `human-review` gate, now shows an **Approval** badge under Waiting on others instead of **Fix CI**.
- The Todo page is gone, along with its list, the todo picker in new sessions, todo links in messages, and the todo tool sessions used to add items to it. Settings › Sync no longer carries a todo list.
- A new branch or Board task in a repository whose origin was added by hand, not cloned, now starts from its main branch instead of failing with a git usage message.
- **Merge on main** on a Board task now merges right away from the server, without starting a session; a session starts only if the merge fails.
- Each Board task now has its own branch, `board/<id>`, and every session on it starts in that branch's folder, so no session has to look for it.
- A Board session ends itself when it marks its task done, and no longer renews a 15-minute hold on it. Marking done first runs the quick merge checks, so a missing changelog line or an unexplained test edit is fixed by the session that made it.
- Screenshot checks sign in to the page without printing your access token into the session.
- An ended session now reads as finished in the archive instead of interrupted.
- A Board Workspace's **Projects** tab now lists its projects in a resizable column with search, **All projects**, and **New project**, as the **Bots** tab does; a project you pick opens on the right, beside the list.
- Each reply in a Board thread has a **Mark unread** button, as in Slack: it closes the thread and its blue unread count comes back, counting from that reply, until you open the thread again.
- The Board looks calmer: reply counts and unread counts use the app's own colors instead of bright blue, names drop the **SESSION** tag and use one size, the open Board task is marked in gray instead of yellow, the last reply's time no longer turns into "View thread" on hover, and messages line up with the Board's title.
- An empty Board reads "Each message here becomes a Board task, and a session starts working on it", its message box reads "Message <Workspace> to start a session", and the Board shows gray placeholder rows while it loads.
- Each reply in a Board thread has a **Mark unread** button, as in Slack: it closes the thread and its unread count comes back, counting from that reply, until you open the thread again.
- A Board task's message in the channel has **Mark unread** too, which counts its whole thread as unread again.
- **Notifications** and **Settings** in the Board's sidebar now open with the sidebar still on the Board, instead of switching it to Sessions.
- The Board's **Bots** page and its sidebar group now list only the Bots that work across projects, those whose folder holds your projects, such as `~/code`. A Bot that belongs to one project shows in that project's **Bots** tab on the Board.
- A Board thread now shows what each session did right under that session's reply, instead of in one **Actions** card at the bottom, without the "Actions" heading: each line is just the Git, GitHub, or Linear logo and the branch, pull request, or issue name, with what the session did with it on hover.
- A Board Workspace's **Bots** and **Settings** tabs now look like the Sessions side's pages: the Bots tab lists its Bots in a resizable column with search, and the Settings tab lists its sections with **Search settings**. The **Memory** tab now fills the width, with the open memory beside the list.
- A Board session now asks first only when your message is unclear, such as when it could mean two different changes. A clear request, such as "Merge on main" or a plain "make the button blue", runs right away.
- Behind the scenes: the agent's always-loaded instructions shrank from about 6,000 tokens to about 900. Rules only some tasks need, such as design handoff, pull-request reviews, and subagent worktrees, now live in skills that load when the task needs them.
- Behind the scenes: the Escape key that closes a Board thread, a link preview, or an inline confirm now goes through the shortcut table, and two more large source files are split under the size limit.
- Behind the scenes: a new lint rule keeps page-wide keyboard shortcuts in the one shortcut table, and the two largest source files are split under the size limit.
- A Bot, a project, or a pull request you open from a Board Workspace's tab now opens inside that tab, with the Workspace and its tabs still showing, instead of jumping to the Sessions side's page. Its links, a Bot's routines and a pull request's files included, stay in the tab, and a Bot in the Board sidebar opens in its own Workspace's **Bots** tab.
- A Board session now talks before it builds. Unless your message names the exact step, such as "Merge on main", it first replies in the thread with what it understood, the change it would make, and its questions, and starts work only once you answer.
- Behind the scenes: every lint rule now has a sample file it must flag, so a rule that quietly stops working fails the checks, and a new rule can start with its old findings listed and only ever shrink them.
- Notifications now appear at the top center of the window, and every one, including those still working, has a close button.
- The Board's tabs are back under the Workspace's name: Messages, Bots, Pull requests, Memory, Projects, and Settings.
- Board threads no longer suggest ending the session, which a Board session does by itself.
- A Board thread now ends with an **Actions** card listing what its sessions did, the Linear issues they saved, the branches they worked on, and the pull requests they opened, so you see it before you merge.
- Behind the scenes: an eval run now stops when a task's hidden tests could not run, such as with Docker down, instead of scoring every run after it as the model's failure.
- The comment count on each Pull requests row now counts only unresolved review threads, and hides when none are left open.
- Opening a Board thread from the message list now always shows its Thread tab first, not the session's conversation.
- The Board no longer starts a second session on a task while the session working on it is still busy. Under heavy load a session could miss renewing its claim, and the Board then kept starting new sessions on the same task, about 30 for one task, each stopping because another held it.
- Each Workspace in the Board sidebar now has a chevron that hides or shows the Board sessions listed under it; clicking the Workspace's name still opens its Board.

## 2026-11-25

- A finished Board task's suggested next steps now sit under the thread's reply box, as they do under a session's composer, with the same keys: Enter sends one, Tab fills it in to edit first. They no longer show as buttons under the last message.
- A Board thread summary now shows omp's mark once, however many sessions replied, instead of one identical mark per session.
- A Board task whose session stopped for you now says so in the Board's message list, in amber, in place of "Working on it…": "Asks you" with its question, "Waiting for your input", or "Waiting for your reply". Clicking a question opens the session's conversation, where you answer it.
- A Board session that changes something you can see now puts its screenshots in the message that closes the task, so the thread shows them.
- Board messages from a session now show omp's mark as the picture and "omp agent" as the name, with the session's title beside it, instead of the title's first letter on a color as if the session were a person.
- The Board sidebar now has **Notifications**, with its unread count, and **Settings** rows above the Workspaces, as the Sessions sidebar does.
- The Board sidebar's Bot groups now look and fold like the workspace groups in Sessions, smaller than before, and the Workspaces and Bots headers each fold their whole list.
- A Board task that already has a thread now shows "Working on it…" inside its thread summary, in place of "Last reply", with the working session's face first, as Slack does, instead of a second row under it.
- The Board sidebar's Bot groups, Pinned, each section, and Other Bots, now fold open and shut when you click them, instead of opening the gallery of every Bot.
- You can now edit your own messages on the Board and in a Board thread: hover one, click the pencil (**Edit message**), change it, and press Enter or **Save**. The session working on it stops what it was doing and picks up the new text; the message shows "(edited)".
- Clicking a session on the Board, in its sidebar, on a message's author, on "Working on it…", or with **Open its session**, now opens that session's conversation in its Board thread instead of leaving the Board for Sessions.
- Board sessions no longer merge their own work. Each ends by telling you in its Board thread what it did and suggesting next steps, such as Merge on main, then stops.
- Click a suggested next step under a finished Board task, or type a reply, and a new session takes it from there with the whole thread.
- A Board task's thread summary now shows a small blue pill with the number of replies you haven't read yet, as in Slack; opening the thread clears it.
- The Board now jumps to the bottom when you post a message or reply in a thread, even if you had scrolled up, and keeps following new messages from there; a thread opened on a picked reply holds still until you reply.
- The Board's **Bots** group now lists the Bots under your own groups, Pinned, each section, and Other Bots, instead of one All Bots row, with smaller faces.
- The Board's sidebar now has a **Bots** group under the Workspaces: **All Bots** shows every Bot, whatever its Workspace, and each Bot is listed under it. A Workspace's **Bots** tab still shows only the Bots kept to it.
- The tab row under a Workspace's name on the Board is gone; the Board shows its tasks, and the Board thread keeps its own tabs.
- Fixed: the rule under the Board's tabs no longer flickers a pixel up and down when you click a tab.
- A Board task still in work now reads "Working on it…" followed by its session's name, instead of "<session> is on it…", and its open thread shows the same line under the replies.
- The Board's composers now take files: the paperclip, a drop, or a paste attaches images and documents to a Board task or a reply. Images show in the message and reach the session; before, they vanished when you sent.
- You can now search the Board as you search Slack, from the field in its header.
- The Board's search finds the Board tasks and replies holding every word you type, in the open Workspace, the open Board thread, or all Workspaces.
- A Board search result opens its Board thread with the reply highlighted.
- The Board's **Pull requests** tab now lists only the pull requests of that Workspace's repositories, whatever Workspace the sidebar picker shows, so every Board tab keeps to its Workspace.
- Fixed: the browser tool sessions use for screenshots could not save a picture or read a script inside a worktree or in /tmp when the session had started in the main checkout. Run the starter kit's install again to pick this up.
- In the Board's left sidebar, each Workspace now lists only its running sessions; stopped ones no longer show there.
- A Board thread no longer shows grey lines for a session starting on, claiming, renewing, or finishing its Board task; lines for a failed start, a lapsed lease, or a woken session stay.
- A session the Board starts now finishes on its own: it lands its work on `main` (or opens a draft PR where the repository ships through pull requests), posts its outcome in the Board thread, and ends itself, so you no longer merge or end Board sessions by hand. A reply resumes it, and it finishes the same way again.
- A Board thread now shows only what was said: no grey lines at all, and no suggested prompts under its reply box.
- A project made from a Board's **Projects** tab now belongs to that Workspace and shows there right away, before any session joins it; it no longer shows in another Workspace's tab.
- A rule now separates the Board's tabs from the content below them, as in Slack.
- A Board message still in work now shows a shimmering "<session> is on it…" line under it, styled like the reply line, instead of the ready and claimed badges. Board messages no longer show their #number or what they wait on.
- A Board thread no longer gets a "#5 is done, so this Board task is ready" line when the Board task it waited on finishes; its ready badge already says so.
- The Board thread's tab row is now a session's right sidebar: besides **Thread** and the session's conversation, its + opens that session's **Overview**, **Diffs**, **PRs**, **Artifacts**, **Review**, and **Linear** tabs, and a tab you open stays open across threads. A session's right sidebar header line now sits level with the page header beside it.
- The Board now has tabs under the Workspace's name, as a Slack channel does: **Messages**, the Board tasks, then **Bots**, **Pull requests**, **Memory**, **Projects**, and **Settings**, each showing only what belongs to that Workspace; Settings lists just the sections that read one workspace, such as Models, Files, and Worktrees.
- In a Board thread's reply box, typing an at sign now lists your sessions straight away, so a reply can point its session at another one; the other at-sign suggestions stay out of the thread for now.
- A session's Board reply can now suggest what to answer next: the Board thread's reply box lists those prompts, and a click, a number key, or Enter sends one.
- A session the Board starts is now named after its Board task's work, such as "Fix sidebar badge count", instead of "Claim Board task 5 on omp-agents".
- The Board thread's pane now has tabs, as a session's right sidebar does: **Thread** for the Board task and its replies, and a tab named after the session working on it that shows that session's conversation, with its composer while it runs. Its header line now sits level with the Board's.
- A reply in a Board thread now reaches a session even after its Board task is done: it wakes the session that finished it. The reply box is now the full New session composer, so you pick the model, thinking level, and skill the woken session runs on, and the Board's message box drops its workspace picker; the sidebar switches Workspaces.
- On the Board, your messages and replies now show your Slack profile picture when Slack is connected in Settings › Integrations.
- Board messages and replies now show as formatted text, with lists, code, and links, and sessions are told to write their Board replies as a short lead line and a list instead of one long paragraph.
- The Board thread's pane can be resized: drag its left edge, and the page remembers the width. Its reply box is now the session composer, with suggestions when you type a slash or an at sign, dictation, and an unsent reply kept per thread.
- The Board's header now matches the other pages, its message box spans the channel, messages use the app's text size, the thread pane narrows on small windows, and Escape closes the thread wherever the cursor is.
- In the Board tab of the sidebar, a Workspace's sessions now sit a little apart from the Workspace above them.
- The Board now looks and works like a Slack channel: pictures and names on each message, messages grouped by author and split by day, a reply line under each message, a hover toolbar with **Reply in thread**, and a Slack-style thread pane that Escape closes.
- The dashboard uses less CPU with many sessions open: idle sessions no longer check their running programs every 10 seconds, and the session list only resends rows that changed.
- Long replies stream more smoothly: only the part still being written is redrawn, instead of the whole reply on every word.
- Pull requests refresh with fewer GitHub calls at once, so the dashboard stays under GitHub's limits.
- Opening the dashboard with very large sessions uses less memory, and searching conversations is faster.
- The Board's message box is now the New session composer: pick the model, thinking level, and skill the session starts on, with `/` suggestions and dictation; the **Needs** picker is gone, and the thread's reply box uses the session composer.
- The Board now has its own tab at the top of the sidebar, beside Sessions; under it the sidebar lists the Board's workspaces and their sessions, and the page gets the full width.
- New **Board** page: post a message in a workspace and a new session starts on it as a Board task; pick what it **Needs** so it waits for another one to finish, follow each one's thread on the right, and reply to reach the session working on it, which wakes it if it stopped.
- Sessions get a `board` tool to post, claim, and finish Board tasks; a claim lasts 15 minutes unless renewed, and a Board task whose session went quiet gets a new one.
- Behind the scenes: the Board keeps an append-only log in `board-events.jsonl`, and stored modules can run their own background work.
- `/ship` now runs the no-comments pass at the end of Implement, before the checks and the draft PR, so reviews start from a diff without stray comments.
- A long question from a session now reads as a bold first line over plain text that keeps its line breaks and lists, instead of one wall of bold text.
- A session asking several questions now offers Next beside Back once a question is answered, so you can move both ways between them.
- Fixed: a dev server or test browser that a session started in the background, such as with nohup, now counts as that session's process, so it stops once the session sits idle or ends instead of running on and filling the Mac's memory.
- Apps a session opens, such as Docker Desktop, stay running when the session ends.
- Behind the scenes: a decay check now scores the runs that drop a skill or extension, where before every such run failed its tests because the run's folder name held a colon.
- Behind the scenes: menus, dialogs, tabs, tooltips, and the command palette now run on one interface library, UI SDK, in place of three, so they behave the same way everywhere.
- The New session page has a Background menu in its header: pick Retro grid, Aurora, Fire, Eclipse, Black hole, Horizon, Galaxy, or Globe; the dashboard remembers your pick.
- A session waiting on CI no longer lists its pull requests under its row; its row shows a clock with how many still wait on checks and a red cross with how many fail.
- Fixed: the "routine runs exited early" notification no longer lists a run that started late only because the Mac was asleep, such as the catch-up runs when you open the lid.
- Fixed: a routine set to post its output When it fails no longer counts as exited early each time it hands work to its Bot on purpose.

## 2026-11-24

- The session details sidebar's Overview tab has a Jobs section that lists the commands the agent runs in the background, live, with how long each has run and its last line of output.
- When a job's output counts its progress, such as 23/60, its row shows a progress bar, the pass and fail counts, and about how long is left.
- Click a job to read its last 15 lines as they come in; a job that fails opens by itself and shows in red.
- A session's row in the left sidebar shows a small spinner and a count while it runs background jobs, even when its agent is idle.
- Each Your move row shows the session its fix goes to, or "no session", the badge's tooltip says where the fix goes, and the heading buttons ask, for example, "Confirm 4? · 3 to sessions, 1 new".
- Fix CI, Address comments, and Resolve conflicts on a pull request now go to the session that already worked on it, resuming that session if it ended, instead of starting a new session each click.
- Reply and Fix CI at the top of Your move do the same for each pull request, and start a new session only for a pull request no session worked on.
- A step in a project's plan has a play button: it opens a new session in the project, already set to work on that step and its sub-steps, with the prompt written for you.
- An eval run that a session starts with the eval runner now shows in that session's Subagents list, with the task it works on while it runs, then whether it passed, its cost, and its minutes; click it to read the run's conversation.
- The prompt that Start session writes for the steps you picked now asks the session to tick each one it finishes.
- Sessions waiting on a pull request's checks or a scheduled send now sit in one top-level Waiting section between the workspaces and Past, each with a line per pull request showing whether its checks are running, failing, or passing; click a line to open the pull request.
- Once every pull request a session watches passes its checks, the session leaves Waiting on CI and shows the blue dot, so you see that CI went green without being pinged.
- A session waiting on a scheduled send keeps the calendar clock.
- The sidebar's **Scheduled** group is gone; scheduled messages still show above their session's composer with **Send now**, **Edit**, and **Cancel**.
- A session that ended its turn to wait on a scheduled check, such as a follow-up it scheduled or a pull request it watches, no longer shows the blue idle dot: its row shows a calendar clock, it lists with the sessions waiting on work, it adds nothing to the waiting count, and the idle stop no longer ends it.
- The extension tests now run against a temporary omp config, so a killed test run can no longer leave a broken test marketplace in your `~/.omp` that makes `omp plugin marketplace update` fail.
- The Board is gone: its page, channels, threads, and the board tool agents used to post there.
- Projects keep working on their own: the Projects page, the brief each session in a project gets, and the project_list and project_update tools agents use.
- Your existing projects move over by themselves the first time the dashboard starts, with their plan, decisions, and messages as log lines; the Board's leftover inbox folder is deleted.
- Agents can add a whole project plan, with its sub-steps, in one project_update call.
- The eval set's 11 tasks that failed the same way in every run now tell the agent the interface their checks expect, such as an exact error message, a dependency's name, or an output's shape, so a run is no longer failed for guessing a name differently.
- The eval runner takes `--jobs N` to run N tasks at once; each run and its recorded result stay the same, only the wall time drops.
- A done Board thread with messages you have not read now stays in its channel's list, and in the channel's unread badge, until you open it; before, the badge counted it while the list hid it.
- The eval set now scores what its tickets ask for: each run sees the pull request's description, only the tests that the change made pass decide the score, and a new column shows the share of those tests that passed. Runs can now use git, uv, and vitest inside their clone.
- When a land stops because an existing test changed, its message now says exactly how to mark the change as intended, or to put new tests in a new file instead.
- A new Friday routine receipt, off until you turn it on, lists what each routine did and cost this week and says which to keep, slow down, or retire.
- Each routine now shows what its runs cost: the row adds up the Bot's turns over the kept runs, and an open run shows its own tokens and cost.
- A Bot now ends a routine run that found nothing new quietly by default, with no notification and no unread dot, so only runs with news reach you.
- New routines, whether you or a Bot create them, now start with New conversation each run checked, so each run no longer re-reads the Bot's whole earlier conversation. Your existing routines keep their setting.
- A routine that runs a command can now post its output to the Bot only when the command fails or prints something different from last time: pick When it fails or its output changes in the routine's editor. A cheap check can then run often and wake the Bot only on news.
- Wake-up messages the dashboard sends a session no longer show in its conversation: a watched pull request's change, a Board mention, and a follow-up the agent scheduled for itself. The agent still reads and acts on each one. Messages you schedule yourself still show.
- New conversation each run now works for routines that run a command too: when the command's output is posted to the Bot, it opens a new conversation. A run that posts nothing leaves the conversation alone.
- A routine that sends a message can now start a new conversation on each run: check New conversation each run in the routine's editor. When the Bot is busy, the run's message joins the current conversation as before.
- A Bot or session that answers you in a Board thread now ends its post on suggested prompts when it leaves you a next step, so the reply box offers them as it does under a session's "finished" post.
- A Bot whose conversation stopped still offers the prompts its last reply suggested under its composer.
- Settings › Sync can now carry your Board projects between machines: each project's name, goal, decisions, archive, and plan steps with their state arrive on every machine, while its sessions and messages stay where they happened.
