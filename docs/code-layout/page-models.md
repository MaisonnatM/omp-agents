# Page: list models, sidebar tabs, model menu, and mentions

- `web/pull-request-checks.ts`: `presentChecks`, the detail tab bar's checks text, popover heading, aggregate state, and stable attention, running, and completed groups.
- `web/changes-model.ts`: `folderTree`, the tree of folders that the changes explorer and the notes list share, and `fileTree`, the explorer's, where a folder holding one folder and no file joins it, then the diff's folded runs, the file view's gutter marks, the diff list's sizes and `lastAtOrAbove`, which finds the file at the top of its scroll, and `changesPathOf`, which finds a card's file path in the session changes list.
  `shortPaths` adds the fewest parent folders needed to tell files of one name apart in the Todos card's **Files** section.
  `web/components/changes/file-tree.tsx` draws the explorer's tree; `web/code-highlight.ts` cuts `lowlight`'s syntax colors into lines, for the changes view, recorded edit diffs, and a message's code blocks.
  `web/loaded-once.ts` holds `loadedOnce` and `useLoaded`, a value a dynamic import makes, loaded once on first need, which the grammars and `web/components/raw-html.ts`'s raw HTML plugins use.
- `web/file-paths.ts`: which paths in agent text name a text file, an image, or a video (`linkedFile`), the absolute path each resolves to, and the `figure` that `remarkFilePaths` ends the text with, listing the images and videos it names.
  `web/delimited.ts` parses a TSV or CSV file into rows.
  `web/components/file-link.tsx` holds the link that opens such a path, `web/components/local-media.tsx` the image or video shown in place and the thumbnails under the text, and `web/components/file-dialog.tsx` the dialog that shows the file, an image or video large.
  That dialog and `FileChangesDialog` in `changed-files-section.tsx` share `ViewerDialog` from `web/components/viewer-dialog.tsx`: the header with its actions and close button, and the body that takes focus and scrolls.
  `web/components/file-diff.tsx` draws each recorded edit as a Kobra-inspired card with old and new line numbers, syntax colors, a fixed gutter, and a horizontal code scroller.
  `editHunks` in `src/shared/transcript.ts` converts omp's numbered diff into hunks with both line numbers.
  The new-issue and new-event dialogs share `FormDialog` and `FormDialogHeader` from `web/components/form-dialog.tsx`: the dialog that stays open while its form sends, the header with its title, actions, and close button, and the `Submit` state, error line, and Cmd+Enter check that both forms use.
  `sessionsOn` in `web/sessions.ts` picks the running sessions that work on a pull request or an issue, which the Pull requests page and the tickets page show.
  `web/pull-requests-model.ts` holds the pull requests' moves in one table, `MOVES`, with each move's verb, its section, and the quick action that makes it, over `moveOf` in `src/shared/moves.ts`.
  It also holds which sections start folded, sorts rows by move, and keeps each stack's rows together by the chain of base branches.
  `rebaseApplies` decides which pull requests offer **Rebase on** their base, and `rebaseOrder` lists what **Rebase behind** rebases: those, and the pull requests stacked on them, bottom of each stack first.
  `boardColumns` lays the board's columns out, one per section over every readable repository, `shownBoardPullRequests` lists the cards of its open columns in order, and `boardDrop` decides what dropping a card on another column does: the quick action, the merge confirmation, the draft state change, or a refusal with why.
  `commentCount` counts the comments that the **Timeline** tab and its header show, and `withThreadResolved` keeps a thread's state and unresolved count, with how many of the open threads a bot started, together.
  `threadStarters` gives a **Reply** row's count of the open threads AI and people started, and its tooltip.
  `web/pull-request-comments.ts` combines Summary conversations, filters bot and completed discussions, and pages recent conversations before ordering them.
  `PullRequestOrder` there is the order you chose, the repositories, the sections, the sort, and the manual order of pull requests, which `placedManual` updates after a drop; a stack moves as one `unit`.
  `withPullRequestState` gives the list after GitHub took a state change from a row or a merge, until the list is read again: a closed pull request leaves it, and every other repository and row stays the same object.
  `withPullRequestReviewers` does the same for a review asked or withdrawn, through `withReviewer`, which the **Summary**'s Reviewers picker shows at once too.
  `web/routines-model.ts` words a routine's schedules and triggers, task, next run, and last run, and turns the routine editor's form into the routine it saves.
  `web/calendar-model.ts` lays a month's routine runs, past and planned, its due todos and tickets, Google events, and the events kept on this computer out by day, both kinds of event as one `ShownEvent` with its color, its place, and its source, whose `ref` is the `EventRef` that deletes it, `null` for an event of a Google calendar you may only read.
  It also lists the new-event dialog's calendars with `calendarChoices`, and `keptChoice` finds the one localStorage kept among them, reading a choice saved before accounts as the first listed calendar of its id.
  `src/shared/days.ts` names a local day as todos, tickets, the calendar, and the activity fold do, `YYYY-MM-DD`, finds the local midnight that starts one, walks the days between two of them, and turns minutes after midnight into a time input's `HH:MM` and back, for the routine editor and the new-event dialog; `DAY_MS` is a day's milliseconds.
- `web/page-icons.ts`: the icon of each dashboard page, which its sidebar tab and every link into the page show.
  `web/routing.ts` owns the sidebar tab vocabulary, each tab's place, the bar or the header, the settings sections, and the page/hash routes; `web/components/workspace-picker.tsx` owns the directory picker and the workspace rows it shares with the sidebar's workspace picker.
- `web/sidebar-tabs.ts`: the sidebar's tab layout, the tabs' order and which ones the user hid, which **Settings › Preferences** edits and `useSidebarTabs` keeps in localStorage under `omp-agents.sidebar-tabs`; `decodeTabLayout` reads it back with every tab once, `shownTabs` gives the tabs shown, `placedTabs` those at one place, the bar's, which it draws and the position keys count, or the header's, `positionKey` gives the position key each tab takes, `shortcutRows` gives the rows the reference dialog shows, and `positionHandlers` builds the page-wide handlers for the position keys.
- `web/components/settings/settings-nav.tsx`: the Settings sidebar's links, one per section of `SETTINGS_SECTIONS` in `web/routing.ts`, grouped by each entry's `group` into **Usage**, **General**, **Connections**, and **This workspace**; each entry's `keywords` let the command menu find it under **Settings**.
  The open section is in the hash, `#settings/<section>`, and the **This workspace** sections follow the sidebar's workspace; `settings-page.tsx` keeps inactive panels mounted to preserve unsaved drafts, and shows the workspace picker on the **This workspace** sections only, under the header line each one's `meta` in `SETTINGS_SECTIONS` gives.
  `preferences-tab.tsx` holds the choices the app keeps in localStorage and **Stop idle processes**, which `/api/process-settings` keeps on the server, and `routing-tab.tsx` the Models section: roles, model chains, provider order, and retries.
  `workspaces-tab.tsx` lists the workspaces with **Hide**, the hidden ones with **Show**, and adds a directory by path through `PUT /api/workspaces`; the list it shows comes back as the `workspaces` socket message.
  `source-control-tab.tsx` shows the `gh` and `gt` rows, the automatic pull switch, each repository's override with its last pull, and the default merge method, which `web/merge-method.ts` keeps in localStorage with the method of the last confirmed merge.
  `sync-tab.tsx` saves the remote and branch, runs a sync, shows the last outcome and, on a conflict, each file's two versions with **This machine** and **Remote**, and switches each synced item through `PUT /api/sync`.
  `worktrees-tab.tsx` lists the Git worktrees of the repositories sessions ran in, with what uses each and which merged, and removes them one by one or, through **Remove merged**, every merged one nothing blocks, previewing and removing in batches of `MAX_WORKTREE_BATCH`.
  `decisions-tab.tsx` shows the workspace repository's decision records from `GET /api/decisions` as a timeline and renders an opened one with `MessageMarkdown`, against the records directory, so its relative links open in the file dialog.
  `workflows-tab.tsx` lists the workflows that `GET /api/settings` names, each with its `/name` or `/skill:name`, finds each one's skill among the response's `files` by path, and opens the selected one in `FileView`, which it imports from `files-tab.tsx`.
- `web/components/settings/analytics-tab.tsx`: the Settings section for request usage, including time-range buttons, a token chart, breakdowns, and the top sessions; it polls only while it shows.
  `provider-trend.tsx` renders the stacked provider chart and bucket-data table, loaded with `React.lazy` so `recharts` is a chunk of its own; `analytics-format.ts` shares number and cost formatting across the section; `context-sources.tsx` renders the context-source table with its workspace and session filters.
- `web/components/settings/activity-tab.tsx`: the Settings section for how the dashboard is used, with time-range buttons, the features not or rarely used, the most used, navigation, and active time; it reads only while it shows.
  `activity-chart.tsx` draws the active minutes per day, loaded with `React.lazy` so `recharts` stays a chunk of its own; `range.tsx` holds `useRangedRead` and `RangePicker`, the range read and buttons both tabs share, and `table.tsx` the report tables' `Table`, `RowHead`, `Text`, `Count`, and `percent`, which `context-sources.tsx` uses too.
- `web/model-menu.ts`: what the model menu derives from the model list and plan usage, the context variants of a model, a provider's quota for the account with the most left, and the search's word match.
  The menu itself is `web/components/model-picker.tsx`, built on the submenu, switch, and radio rows of `web/components/ui/menu.tsx`; `Plans` in `web/components/plan-usage.tsx` hands it the last `omp usage` run.
  `web/components/org-icon.tsx` draws a model maker's logo, such as Anthropic's, from svgl.
- `web/mentions.ts`: the composer's `@` menu as a pure function of the draft, the `@` token, the page's lists, and omp's file completions: its categories and their references, the query a token asks, and the rows and sections it shows.
  `web/completion-trigger.ts` reads the token and its prefix from the draft, and `useCompletion` in `web/components/completion-popup.tsx` builds the menu and asks the server only for files.
  `useSearchSources` in `web/reads.ts` gives the menu and the command palette the tickets, polled only while asked for, and the sidebar workspace's pull requests.
- `web/prompt-tokens.ts`: the references a prompt carries as text, which the composer and the transcript draw as chips, read back from what the `/` completion and the `@` menu insert, and from `annotationReference`, the one-line code span the Browser appends for each **Attach**; `remarkPromptChips` marks them in a sent prompt for `MessageMarkdown`.
  `web/components/prompt-chip.tsx` draws one chip, and `web/components/prompt-editor.tsx` is the composer's text field, a Lexical editor whose chips are atomic nodes over the prompt's text, so the draft stays a string.
- `web/components/session-visual.tsx`: `SessionVisual`, a `mermaid` or `chart` fence in a session's message drawn as a diagram image or a chart, with **Preview** and **Source**, Copy, and an expand dialog on `ViewerDialog`, or its text and why when it breaks a rule of `src/shared/session-visuals.ts`.
  A diagram loads `beautiful-mermaid` on first use and shows as a blob URL image, drawn again when `useDarkClass` in `web/theme.ts` sees the theme change; a chart draws through `web/components/ui/chart.tsx` on `recharts`, in `ChartView` from `web/components/session-chart.tsx`, which loads on the first chart.
