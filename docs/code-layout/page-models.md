# Page: list models, sidebar tabs, model menu, and mentions

- `web/pull-request-checks.ts`: `presentChecks`, the detail tab bar's checks text, popover heading, aggregate state, and stable attention, running, and completed groups.
- `web/changes-model.ts`: `folderTree`, the tree of folders a list of files makes, and `fileTree`, the explorer's, where a folder holding one folder and no file joins it, then the diff's folded runs, the file view's gutter marks, the diff list's sizes and `lastAtOrAbove`, which finds the file at the top of its scroll, and `changesPathOf`, which finds a card's file path in the session changes list.
  `shortPaths` adds the fewest parent folders needed to tell files of one name apart in the **Overview** tab's **Files** section.
  `web/components/changes/file-tree.tsx` draws the explorer's tree; `web/code-highlight.ts` cuts `lowlight`'s syntax colors into lines, for the changes view, recorded edit diffs, and a message's code blocks.
  `web/loaded-once.ts` holds `loadedOnce` and `useLoaded`, a value a dynamic import makes, loaded once on first need, which the grammars and `web/components/raw-html.ts`'s raw HTML plugins use.
- `web/overview-subagents-model.ts`: `subagentTree`, the subagents the **Overview** tab's **Subagents** section lists for a view, the descendants of the session's main agent or of one subagent, depth first with each one's depth, siblings in the order the host lists them; `arenaGroups`, which takes out of those rows the runners and judge of each arena with two runners among them, seated A, B, C in the arena's order with what the pick made of each; and `runTime`, how long a subagent has run, up to now while it runs and up to its stop after.
- `web/file-paths.ts`: which paths in agent text name a text file, an image, or a video (`linkedFile`), the absolute path each resolves to, and the `figure` that `remarkFilePaths` ends the text with, listing the images and videos it names.
  `web/delimited.ts` parses a TSV or CSV file into rows.
  `web/components/file-text.tsx` shows a text file for reading: `MarkdownDocument` renders Markdown under the frontmatter the server parsed, which the file dialog and Settings › Files share, and `CodeText` shows any other file, and an artifact's **Source**, as numbered, wrapping, colored lines, breaking a token longer than a line, with no empty line after a final newline.
  `web/components/file-link.tsx` holds the link that opens such a path, `web/components/local-media.tsx` the image or video shown in place and the thumbnails under the text, and `web/components/file-dialog.tsx` the dialog that shows the file, an image or video large.
  `file-dialog.tsx` also holds `AttachedFileDialog`, which shows the text a sent prompt carried as a file as plain numbered lines, the way the model read it, even for Markdown; `web/components/prompt-file-chips.tsx` draws the chips above the prompt that open it, and `Transcript` holds which one is open.
  `MessageMarkdown` opens the images of agent text, and of a pull request's Markdown, through `Openable` and `useMarkdownImages` in `web/components/markdown-images.tsx`: a click shows one in `ImageViewer` with the text's other images, in place or under it, a step away.
  That dialog and `FileChangesDialog` in `changed-files-section.tsx` share `ViewerDialog` from `web/components/viewer-dialog.tsx`: the header with its actions and close button, and the body that takes focus and scrolls, or, given a `Zoom`, zooms.
  `web/components/file-diff.tsx` draws each recorded edit, and each file of a `diff` fence in a pull request's Markdown, as a Kobra-inspired card with old and new line numbers, syntax colors, a fixed gutter, and a horizontal code scroller; it takes rows already split into hunks, and hides the numbers of a fence that has no `@@` header.
  `editHunks` in `src/shared/transcript.ts` converts omp's numbered diff into hunks with both line numbers.
  The new-issue and new-event dialogs share `FormDialog` and `FormDialogHeader` from `web/components/form-dialog.tsx`: the dialog that stays open while its form sends, the header with its title, actions, and close button, and the `Submit` state, error line, and Cmd+Enter check that both forms use.
  `web/components/project-trust-dialog.tsx` builds on them too: `ProjectTrustDialog` lists a refused start's untrusted pieces with **New** or **Changed**, and **Trust and start** calls `trustAndStart` from `web/use-dashboard.ts`, which saves the trust through `PUT /api/project-trust` and sends the start again.
  `sessionsOn` in `web/sessions.ts` picks the running sessions that work on a pull request or an issue, which the Pull requests page and the tickets page show.
  `web/pull-requests-model.ts` holds the pull requests' moves in one table, `MOVES`, with each move's verb, its section, and the quick action that makes it, over `moveOf` in `src/shared/moves.ts`.
  It also holds which sections start folded, sorts rows by move, and keeps each stack's rows together by the chain of base branches.
  `rebaseApplies` decides which pull requests offer **Rebase on** their base, and `rebaseOrder` lists what **Rebase behind** rebases: those, and the pull requests stacked on them, bottom of each stack first.
  `boardColumns` lays the board's columns out, one per section over every readable repository, `shownBoardPullRequests` lists the cards of its open columns in order, and `boardDrop` decides what dropping a card on another column does: the quick action, the merge confirmation, the draft state change, or a refusal with why.
  `commentCount` counts the comments that the **Timeline** tab and its header show, and `withThreadResolved` keeps a thread's state and unresolved count, with how many of the open threads a bot started, together.
  `threadStarters` gives a **Reply** row's count of the open threads AI and people started, and its tooltip.
  `web/pull-request-comments.ts` combines Summary conversations, filters bot and completed discussions, and pages recent conversations before ordering them.
  `PullRequestOrder` there is the order you chose, the repositories, the sections, the sort, and the manual order of pull requests, which `placedManual` updates after a drop; a stack moves as one `unit`.
  `withPullRequestState` gives the list after GitHub took a state change from a row or a merge, until the list is read again: a closed pull request leaves it, and every other repository and row stays the same object.
  `withPullRequestReviewers` does the same for a review asked or withdrawn, through `withReviewer`, which the **Summary**'s Reviewers picker shows at once too.
  `web/routines-model.ts` words a routine's schedules and triggers, task, next run, and last run, and turns the routine editor's form into the routine it saves.
  `web/calendar-model.ts` lays a month's routine runs, past and planned, its due todos and tickets, Google events, and the events kept on this computer out by day, both kinds of event as one `ShownEvent` with its color, its place, and its source, whose `ref` is the `EventRef` that deletes it, `null` for an event of a Google calendar you may only read.
  It also lists the new-event dialog's calendars with `calendarChoices`, and `keptChoice` finds the one localStorage kept among them, reading a choice saved before accounts as the first listed calendar of its id.
  `src/shared/days.ts` names a local day as todos, tickets, the calendar, and the activity fold do, `YYYY-MM-DD`, finds the local midnight that starts one, walks the days between two of them, and turns minutes after midnight into a time input's `HH:MM` and back, for the routine editor and the new-event dialog; `DAY_MS` is a day's milliseconds; and `DAY_KEYS`, `addDays`, `daysApart`, `weekdayOf`, and `mondayOf` name, move, and count the days of a Sport week on the calendar alone.
- `web/page-icons.ts`: the icon of each dashboard page, which its row in the sidebar's page list, its header tab, and every link into the page show.
  `web/routing.ts` owns the sidebar tab vocabulary, each tab a row of the sidebar's page list, the settings sections, and the page/hash routes; `web/components/workspace-picker.tsx` owns the directory picker, which lists the workspaces, and the workspace rows it shares with the sidebar's **Workspaces** label.
- `web/sidebar-tabs.ts`: the sidebar's page list layout, the tabs' order and which ones the user hid, which **Settings › Preferences** edits and `useSidebarTabs` keeps in localStorage under `omp-agents.sidebar-tabs`; `decodeTabLayout` reads it back with every tab once, `shownTabs` gives the tabs shown, less the signed-out ones that `useSignedOutTabs` gives, which the page list draws and the position keys count, `positionKey` gives the position key each tab takes, `shortcutRows` gives the rows Settings › Keyboard shows, and `positionHandlers` builds the page-wide handlers for the position keys.
- `web/components/settings/settings-nav.tsx`: the Settings sidebar's links, one per section of `SETTINGS_SECTIONS` in `web/routing.ts`, grouped by each entry's `group` into **Usage**, **General**, **Connections**, and **This workspace**; each entry's `keywords` let the command menu find it under **Settings**.
  The open section is in the hash, `#settings/<section>`, and the **This workspace** sections follow the sidebar's workspace; `settings-page.tsx` keeps inactive panels mounted to preserve unsaved drafts, and shows the workspace picker on the **This workspace** sections only, under the header line each one's `meta` in `SETTINGS_SECTIONS` gives.
  `preferences-tab.tsx` holds the choices the app keeps in localStorage and **Stop idle processes**, which `/api/process-settings` keeps on the server, `keyboard-tab.tsx` the Keyboard section, every row of `shortcutRows` in a section per category, and `routing-tab.tsx` the Models section: model profiles, roles, model chains, provider order, and retries.
  `workspaces-tab.tsx` lists the workspaces with **Hide**, the hidden ones with **Show**, and adds a directory by path through `PUT /api/workspaces`; the list it shows comes back as the `workspaces` socket message.
  Its **Trusted projects** section lists the `project-trust` socket message's projects, and **Stop trusting** sends `PUT /api/project-trust` with `{ op: "forget", root }`.
  `source-control-tab.tsx` shows the `gh` row, the automatic pull switch, each repository's override with its last pull, and the default merge method, which `web/merge-method.ts` keeps in localStorage with the method of the last confirmed merge.
  `sync-tab.tsx` saves the remote and branch, runs a sync, shows the last outcome and, on a conflict, each file's two versions with **This machine** and **Remote**, and switches each synced item through `PUT /api/sync`.
  `worktrees-tab.tsx` lists the Git worktrees of the repositories sessions ran in, with what uses each and which merged, and queues removals through inline-confirmed **Delete**, **Delete N worktrees**, and **Remove N merged** buttons.
  `web/worktree-removals.ts` holds that queue: it previews each run in batches of `MAX_WORKTREE_BATCH`, removes one worktree per request under one loading toast per run, records when each went so the tab drops it from a list read before then, and keeps each row's **Queued** or **Removing** state across navigation.
  `web/queue-states.ts` keeps where each item of a page-wide queue stands as a map components subscribe to; this queue and the rebase queue in `web/pull-request-rebases.ts` each keep one.
  `decisions-tab.tsx` shows the workspace repository's decision records from `GET /api/decisions` as a timeline and renders an opened one with `MessageMarkdown`, against the records directory, so its relative links open in the file dialog.
  `workflows-tab.tsx` lists the workflows that `GET /api/settings` names, each with its `/name` or `/skill:name`, and finds each one's skill among the response's `files` by path.
  Authored workflows open in `FileView` from `files-tab.tsx` with `settingsFiles`, the saver that writes through `PUT /api/settings/file`; packaged workflows show read-only source with **Manage package**, covered by `web/components/settings/workflows-tab.test.tsx`.
  `omp-memory-tab.tsx` shows the backend bar, built from the `memory.backend`, `autolearn.enabled`, and `autolearn.autoContinue` rows of `agentSettings` and saved with `saveAgentSetting`, then `GET /api/omp-memory`: what a new session gets, and the backend's store, with file stores in `FileRail` and `FileView`, row stores, and destructive actions armed with `useInlineConfirm`.
  `omp-settings-tab.tsx` shows `agentSettings` from `GET /api/settings` by omp's tabs, with one control per row that saves through `PUT /api/settings/agent`, and links to **Files** through the file selection `settings-page.tsx` holds for `files-tab.tsx`.
  `agents-tab.tsx` previews discovered agents as expandable rows, keeps their model-override drafts mounted through search and folding, clears missing overrides, and picks its four execution rows from the same `agentSettings` response.
  `editor.tsx` holds the shared `SettingRow` and native controls, `FileLink`, `LayerNotes`, `EditBar`, and `useEditor`; its `saveAgentSetting` queues an agent-setting write through `writeOrReload`, which refreshes after a conflict, while `useSaving` tracks immediate saves.
  `selector-picker.tsx` is the model and thinking picker shared by Models and Agents; Agents also offers model-role aliases.
  `web/omp-settings.ts` holds `ompSettingsFiles`, the config files the sections link to, and what it shows of a row: `OWNED_SETTINGS` and `ownerOf`, the settings another section edits by id; `valueOf`, `isChanged`, and `formatValue`; and `shownTabs`, each tab's groups for a search, with the owned rows counted per section.
  Agents' owned ids come from `AGENT_SETTINGS` in `src/shared/agents.ts`, also used by the server's entry parser and the execution-row filter.
  `files-tab.tsx` holds `FileRail`, a rail of files as folders with a filter, drawn by `FolderRows` in `web/components/folder-rows.tsx` with `useFolders` keeping which folders are open, which the changes explorer's `FileTree` shares, and `FileView`, one file viewed and edited in place, which `Files`, Workflows, and omp memory share.
- `web/components/settings/analytics-tab.tsx`: the Settings section for request usage, including time-range buttons, a token chart, breakdowns, and the top sessions; it polls only while it shows.
  `provider-trend.tsx` renders the stacked provider chart and bucket-data table, loaded with `React.lazy` so `recharts` is a chunk of its own; `analytics-format.ts` shares number and cost formatting across the section; `context-sources.tsx` renders the context-source table with its workspace and session filters.
- `web/components/settings/activity-tab.tsx`: the Settings section for how the dashboard is used, with time-range buttons, the features not or rarely used, the most used, navigation, and active time; it reads only while it shows.
  `activity-chart.tsx` draws the active minutes per day, loaded with `React.lazy` so `recharts` stays a chunk of its own; `range.tsx` holds `useRangedRead` and `RangePicker`, the range read and buttons both tabs share, and `table.tsx` the report tables' `Table`, `RowHead`, `Text`, `Count`, and `percent`, which `context-sources.tsx` uses too.
- `web/model-menu.ts`: what the model menu derives from the model list and plan usage, the context variants of a model, a provider's quota for the account with the most left, and the search's word match.
  The menu itself is `web/components/model-picker.tsx`, built on the submenu, switch, and radio rows of `web/components/ui/menu.tsx`; `Plans` in `web/components/plan-usage.tsx` hands it the last `omp usage` run.
  `web/components/org-icon.tsx` draws a model maker's logo, such as Anthropic's, from svgl.
- `web/mentions.ts`: the composer's `@` menu as a pure function of the draft, the `@` token, the page's lists, and omp's file completions: its categories and their references, the query a token asks, and the rows and sections it shows.
  `web/completion-trigger.ts` reads the `@` token and its prefix, the `/` that opens omp's commands at the prompt's start, or the `$` that opens its skills, from the draft, and `useCompletion` in `web/components/completion-popup.tsx` builds the menu, asks the server only for files, commands, and skills, and sends a `$` to omp's completion as the `/skill:` it completes.
  `useSearchSources` in `web/reads.ts` gives the menu and the command palette the tickets, polled only while asked for, and the sidebar workspace's pull requests.
- `web/prompt-tokens.ts`: the references a prompt carries as text, which the composer and the transcript draw as chips, read back from what the `/`, `$`, and `@` menus insert, and from `annotationReference`, the one-line code span the Browser appends for each **Attach**; `remarkPromptChips` marks them in a sent prompt for `MessageMarkdown`.
  `web/components/prompt-chip.tsx` draws one chip, and `web/components/prompt-editor.tsx` is the composer's text field, a Lexical editor whose chips are atomic nodes over the prompt's text, so the draft stays a string.
- `web/review-pages.ts`: `parseReviewPages`, the pages a `review-pages` fence lists, on this computer, each once, up to 8; `latestReviewPages`, the last valid list of a settled reply, which the Browser reads from its session's transcript; and `samePages`, which keeps the Browser from rendering again until the list changes.
  `requestReview` holds a **Review visuals** click for its session's Browser, which reads it once with `takeReview` and hears of it through `onReviewRequest`.
- `web/terminal-requests.ts`: `requestNewTerminal`, which asks the terminal panel for a new shell from elsewhere on the page, and `onNewTerminalRequest`, through which the panel hears of it.
- `web/artifacts-model.ts`: `artifactsOf`, a transcript's saved artifacts with their numbered versions, the most recently saved first, a save whose bytes equal the version before it folded into that version; `versionNumber`, the number of the version a card's save belongs to; `pickedVersion`, the version a pick names, falling back to the latest; and `landedSaves`, the saves an `items` delta newly finished.
  `web/artifacts-model.test.ts` covers the grouping, folding, numbering, fallbacks, and a replayed delta.
- `web/artifact-requests.ts`: `pickArtifact` sets the view's pick, the version the **Artifacts** tab shows; `applyItems` applies an `items` delta and, for each save it newly finished, picks that artifact's latest version and tells `onArtifactsReveal`'s listener in `web/app.tsx`; `openArtifact`, a card's **Open**, picks its version and tells `onArtifactOpen`'s listener; `showArtifact` and `useShownArtifact` hold the version the open tab shows, so its card reads **Showing**.
- `web/artifact-links.ts`: `useArtifactVersion`, a version's capability address from `GET /api/artifact-link` and its text, which every kind waits for before it draws, each asked once per page load.
  `web/artifact-links.test.ts` mounts readers in React and covers two readers sharing one link and one text read, and a failed text being asked again once a reader mounts.
- `web/components/session-visual.tsx`: `SessionVisual`, a `mermaid` or `chart` fence in a session's message drawn as a diagram image or a chart, with **Preview** and **Source**, Copy, and an expand dialog on `ViewerDialog`, or its text and why when it breaks a rule of `src/shared/session-visuals.ts`.
  A diagram loads `beautiful-mermaid` on first use and shows as a blob URL image, drawn again when `useDarkClass` in `web/theme.ts` sees the theme change; a chart draws through `web/components/ui/chart.tsx` on `recharts`, in `ChartView` from `web/components/session-chart.tsx`, which loads on the first chart.
