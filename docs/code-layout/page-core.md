# Page: shell, state, and models

- `web/app.tsx`: the page shell.
  It builds the two dashboard contexts and lays out the sidebars, the page, the command palette, and the dialogs, and leaves each slice of state to a hook of its own.
  `web/use-workspace-scope.ts` holds the window's space, which localStorage keeps as the last one picked on this computer, the sessions and workspaces of that space, the selected workspace, which it drops when the space does not hold it, and its pull request poll, scoped to the workspace, else to the space.
  `web/use-focused-session.ts` holds the focused pane's session, the document title, the sidebar following a `/move`, and the space following a session that opens from the other space.
  `web/use-session-lists.ts` holds the Sessions tab's lists and search, the session `latestSession` from `web/sessions.ts` picks from the selected workspace's rows, and pins and unpins through the server's pins, and `web/use-sidebar-tab.ts` the tab and `showTab`, whose Sessions tab opens that session when no pane shows one.
  `web/use-overlays.ts` holds the shortcuts dialog, the command palette, the file dialog, and the new-ticket dialog.
  `web/use-transcript-display.ts` holds how transcripts show tool calls and thinking, and `web/use-page-shortcuts.ts` the page-wide shortcuts and the commands the palette runs.
  `web/use-history-position.ts` follows whether history can go back and forward, which the title bar's Back and Forward buttons and the palette's Go back and Go forward read.
  `web/components/app-sidebar.tsx` wires the roster to the page, `web/components/page-switch.tsx` picks the page or the panes, and `web/components/pane-grid.tsx` lays out the panes.
  `#pull-requests` alone shows the Pull requests page, and the sidebar's Pull requests tab then lists its sections.
- `web/components/get-started.tsx`: the setup dialog, mounted once in `web/app.tsx`, with its welcome, five-step rail, and Back / Next / Skip, the vacant-home eligibility check, and the bottom-right bubble it closes into, drawn under the toasts through `UnderToasts`.
  `web/components/get-started-steps.tsx` draws each step's body, reusing the Settings provider list for the sign-in step.
  `web/get-started-model.ts` holds what it decides without React: `Observation` and `observation()`, `firstSessionFact`, which reads the roster into the first-session fact `web/app.tsx` passes it, and `getStartedSurface`, which picks the dialog, the bubble, or nothing.
  It derives completion from the providers, terminal-session, starter-kit, and source-control reads and the existing global session/integration stores; only dismissal, the closed dialog, and the step on screen are stored locally, never portable completion ticks.
  `#get-started` and the command menu always open the dialog over the home or panes `PageSwitch` draws.
- `web/components/empty-home.tsx`: `EmptyHome`, the neutral home `PageSwitch` draws when no session or page shows, with New session / Get started, any registry error, and, outside the desktop app's title bar, the header's controls at its top right, the space switch among them.
- `web/use-dashboard.ts`: the socket, the page state, and the URL hash.
  One exhaustive switch in the socket's `onmessage` sends each server message to the pane store or the reducer, and the hash is read once into a `Route` (a page, a `#session/<id>` link, or the panes).
  `web/starts.ts` holds the sessions the page is starting, whether new, forked, resumed, resumed all at once, or started by a quick action on a pull request, a Linear issue, or a todo, which runs in the background.
  `request` resolves or rejects on `done` and keeps waiting across a reconnect, whose `resume` hands the server every request still waiting.
  Ending sessions stay in a separate set until their requests settle, even if they have already left the roster.
  A user-data change, such as a note, a todo, a pin, or a Bot, goes out through `write`, which `web/outbox.ts` holds while the socket is down and sends after the next `resume`, so a change made offline is not dropped.
- `web/use-action.ts`: one runner per control, idle, pending, or failed with its arguments, so a second press while it runs starts nothing; it shows failures through the toast manager.
- `web/use-hover-popover.ts`: `useHoverPopover`, the props for a popover a mouse opens by hovering its trigger without moving focus, and a click or Enter opens with focus inside, so its buttons stay reachable by keyboard; the status bar's CPU and a pull request's out-of-date base branch use it.
- `web/use-return-focus.ts`: `useReturnFocus`, the close handler of a dialog shown without a Radix trigger, which gives the focus back to what had it as the dialog opened; the changes explorer, `ViewerDialog`, and `ImageViewer` use it.
  `isReturnedFocus` tells `Tooltip` in `web/components/ui/tooltip.tsx` not to open on that focus, so the next Escape closes what lies under the dialog rather than a tooltip.
- `web/use-phone-width.ts`: `usePhoneWidth`, whether the window is narrower than `PHONE_MAX_WIDTH` from `web/components/sidebar-panel.tsx`, the width the sidebars float under and the `max-phone:` classes key on; the toasts read it for how many show and which way a swipe puts one away.
- `web/use-open-latest.ts`: `useOpenLatest` opens a list's first item once you arrive at it with nothing open, replacing the list's history entry; the Todo page passes its top row, and the Email page its newest conversation.
- `web/open-pull-request.tsx`: a live session's **Open PR**: its prompt, `offeredPrompt`, which sessions offer it, `pressAfter`, where a press stands, in flight until the queue or the transcript's last prompt shows the session took it, then seen until the session is next idle, `useOpenPullRequest`, which keeps the press per session id for the command menu's **Open pull request** in `web/app.tsx` and the header's `OpenPullRequestButton`, and sends with the delivery `deliveryOf` in `web/components/subject.ts` gives the composer.
- `web/pane-store.ts`: each open view's transcript, changed files, images, turns, and completions, outside the page state.
  `useShowTrajectory` registers a view whose Trajectory a component shows, and `useShowConversation` a view whose conversation a page shows outside the panes, as a Bot's page does; `web/use-dashboard.ts` sends both in `watch`, the conversations only while a page covers the panes, and `retainTrajectories` drops the turns of a view no longer shown.
  A component reads one field through a selector hook (`useTranscript`, `useChangedFiles`, `useMedia`, `useComposerData`, …), built on `useSelect` in `web/keyed-store.ts`, which `web/polled-store.ts` shares, one snapshot and subscription per key, and renders again only when that field changes, so a streamed token renders the transcript and what reads `items`, and not the pane, the composer, or the details.
  `transcriptModel` in `web/transcript-view.ts` builds a transcript's blocks, outline, fork points, replies, images, and todo list from the model before, again only from the turn holding the first item a token changed, and keeps the blocks and turns that a token leaves alone as the same objects, so the transcript's rows, its minimap's lines, and its Todos card are memoized on them; what it builds from stays in a private cache, off the model its readers see.
  `Transcript` builds the model once and passes its parts down; a settled row, any but the last, skips its layout and paint while off screen with `content-visibility: auto`, once the row has laid out once and every row has laid out for the current view, tool settings, and lane width, which counts once a resize rests.
  It and the page state apply the server's list updates, the roster's and the past sessions', through `applyDelta` in `web/keyed-list.ts`, which keeps every entry an update leaves alone as the same object.
- `web/dictation.ts`: the page's one dictation capture, kept in memory for the page load, which the composers read with `useDictationState`: starting, listening, or transcribing for one draft, or ended off, with no speech, or with an error; `rowOf` is the status row each phase shows.
  `startDictation`, `stopDictation`, and `discardDictation` send `dictation-start`, `dictation-stop`, and `dictation-discard`, and `applyDictationMessage` applies a `dictation` message, which `web/use-dashboard.ts` routes there with the socket's close; an ended capture's text lands at its saved selection through `replaceInComposer` in `web/composer-drafts.ts`.
- `web/dashboard-state.ts`: the page state and its reducer, which `web/use-dashboard.ts` runs.
- `web/routing.ts`, `web/sessions.ts`, `web/labels.ts`, `web/pull-requests-model.ts`, `web/tickets-model.ts`, `web/routines-model.ts`, `web/calendar-model.ts`, `web/email-model.ts`, and `web/transcript-view.ts`, and `web/document-title.ts` (the tab and window title): the pure transforms from server messages to what the page renders, and the hash routes.
  `workspaceName` in `web/labels.ts` names the personal directory **Personal** wherever a workspace shows, from the directory as shown, and `ALL_OF_SPACE` there names choosing no workspace, **All of Personal** or **All of Work**; `isPrivateHost` in `web/sessions.ts` tells a private session wherever the page marks one.
  `spaceOf`, `sessionsIn`, and `workspacesIn` in `web/sessions.ts` apply `spaces` to the roster and the workspace list, an unknown workspace counting as Work, and `spaceSession` picks the session the panes open on a switch.
  `WindowScope` there is the window's space, its `Spaces`, the selected workspace, and `home`, the personal directory in Personal, which `defaultCwd`, the Todo page, and the sidebar read through `scope` in the dashboard context.
  `web/email-model.ts` folds a conversation's messages into open, closed, and stacked rows with `foldMessages` and `foldsAfter`, words its recipients and lists who wrote in it with `participants`, picks an avatar's letter past a leading English article with `initialOf` and the avatar's colour from the address with `colorIndex`, cuts plain text into links, and builds a message's sandboxed document.
  `src/shared/every-word.ts` holds `everyWord` and `searchWords`, the search rule the sidebar's sessions, the Todo page, the model search, the `@` menu, the command palette's todos, tickets, and pull requests, and the server's conversation search share: every word typed, in any order and any case.
