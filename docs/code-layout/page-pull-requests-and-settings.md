# Page: pull requests, tickets, settings, integrations, and primitives

- `web/components/pull-requests/`, `web/components/tickets/`, `web/components/settings/`, `web/components/integrations/`, and `web/components/new-session.tsx`: the other pages.
  `web/components/new-session-board.tsx` is the New session page's board of todos, sessions, and pull requests above the composer; `web/new-session-board-model.ts` picks and orders its rows.
  `web/components/tickets/tickets-page.tsx` is the tickets page, its list and the open issue beside it in a `ListSplit`, `ticket-row.tsx` an issue's row with its state and priority glyphs and chips, and `ticket-details.tsx` one issue laid out as a pull request's **Summary** is, with a header that condenses through `pull-requests/pr-details/use-condensed-header.ts` above the issue's own scroller, its fields as `MetaRow`s, and `SummarySection`s from `pull-requests/pr-details/section.tsx`.
  `web/components/pull-requests/avatars.tsx` holds the state icons, the avatars, and the reviewers' pictures that a pull request's rows and details share, and `PersonPicture`, the picture beside each person in the **Reviewers** pickers and submenu.
  `web/components/integrations/` holds the integration rows that the Settings page's Integrations section, `web/components/settings/integrations-tab.tsx`, sorts into **Connected** and **Available**: `mcp-integration.tsx` is an MCP integration's row, which `DisconnectedPage` in `disconnected-page.tsx` shows on the tickets and Email pages while Linear or Gmail is not connected.
  `mcp-integration.tsx` draws Linear's and Slack's rows itself and hands Google Calendar's and Gmail's to `GoogleAccountsRow` in `google-accounts.tsx`, which lists each account with its status, **Reconnect** and **Remove**, its workspace links, and what shows below it, such as the calendars `google-calendar.tsx` lists under each Google Calendar account, and offers **Add account**.
  `services.ts` holds what both rows and Settings › MCP servers show of each service: its brand mark, what it gives, its OAuth client's name, the status labels, and `googleApiOff`, the API to turn on for a Google server that answered 403.
  Rows lay out through `integration-row.tsx`, whose `MarkTile` draws a brand mark from `brand-logos.tsx` or a name's first letter; `mcp-integration.tsx` and `google-accounts.tsx` start their sign-ins with `web/use-sign-in.ts`.
  `mcp-connection-controls.tsx` owns what an integration's row and an MCP server's row share about a remote connection: the status labels, **Connect**, the **Reconnect** and **Sign out** items, `SignOutConfirm` and `Confirm`, which ask before a change and show its failure, `ConnectionCallout`, which decides which callout shows, a waiting sign-in first, then the row's question, a failure, a refused sign-in, and an unreachable server, and `useToolList`, the tool count and list.
  Each row keeps its own controls around them: an integration's OAuth client setup and Google's **Enable** link, a server's **Enable**, **Disable**, and **Remove**.
  `slack-app-form.tsx` holds Slack's confidential-app setup, field errors, and scope selection, `google-client-form.tsx` the OAuth client form of a Google service, Google Calendar or Gmail, with each one's API and grant in `GOOGLE_TEXT`, and `client-form.tsx` the steps, fields, and outside links both forms share.
  `web/components/settings/mcp-servers-tab.tsx` is the MCP servers section: `mcp-server-row.tsx` draws each installed server, an integration's server as a pointer to its section with that integration's status, `mcp-catalog.tsx` the **Discover** cards, whose OAuth **Add** signs in through `useSignIn`, and `mcp-server-form.tsx` **Add server**.
  `mcp-logos.ts` holds the catalog vendors' marks as SVG markup in their brand colors, svgl's (https://svgl.app) unless a comment names another source; `brand-logos.tsx` holds the integrations' marks and `BrandMark`, which draws every one of them, black parts in the text color.
  `web/components/settings/providers-tab.tsx` is the Providers section, whose rows reuse `IntegrationList` and `Callout` from `integration-row.tsx`; it reads `providersStore` in `web/reads.ts`, kept in memory only since it names your accounts.
  `provider-logos.tsx` draws each row's mark, keyed by `/login` id: Lobe Icons' (MIT) color marks, or their monochrome ones in the text color for a brand with no color version, svgl's GitLab, Simple Icons' (CC0) Xiaomi, and the name's first letter for a provider none has.
  `web/components/more-actions-menu.tsx` is the ⋯ menu of a row's rarer actions, which the integration rows share.
  `web/components/pull-requests/pull-requests-board.tsx` holds what the sidebar list and the page's list and board share: `usePullRequests`, the pull request list with its order, sessions, and each row's props through `rowBase`; `usePullRequestKeys`, the keys over the pull requests a view shows; and `usePullRequestsBoard`, the list's sections, folds, drag, and rows, with the sort menu and the keys line.
  `usePullRequestsBoard` lays the list out only when the pull request list, its order, or its folds change, and fills in each row's drag, sessions, pending start, and open menu in a second pass; the sessions come from one pass over the roster, `sessionsByPullRequest` in `pr-row.tsx`, and the board keeps a pull request's list the same array while its chips hold, so a memoized row draws again only when what it shows changes.
  Its `onChange`, the same function for every row, sends a row's state change, review request, or merge through `writePullRequest`.
  Only one view of the list mounts at a time, since its rows carry document ids and its keys are global, so `pull-requests-page.tsx` shows the table or the board while the sidebar shows `PullRequestsIndex`, the list's sections as links, or `PullRequestsBoardIndex`, the board's columns as links, and `pull-requests-nav.tsx` lists the pull requests in the sidebar otherwise; `pullRequestsPageShows` decides which, for the page and the sidebar alike, from the view and `usePullRequestDetailsPlacement`, the stored choice of details beside the list or on a page.
  In both views, the page stays mounted while a pull request shows, docking `PullRequestDetails` beside the table or the board in a plain column of the page's full height, as the session sidebar's PRs tab does, so the details keep their header above their own scroller.
  `pull-requests-kanban.tsx` holds `usePullRequestsColumns`, the board's columns with their own folds and keys, which step column by column; it draws the columns, drags a card through `usePointerDrag` in `web/use-pointer-drag.ts` with a card in hand that tilts with its speed, shows each column's slot or refusal, picks a card up with Space for ← and →, and runs a drop's step.
  `pr-page.tsx` shows one pull request's details in the main content, in a frame of its own that lets the **Code** tab fill the height under the header.
  `pr-page.tsx` registers the page-only copy shortcuts, and its back arrow docks the details beside the list again.
  Its `PullRequestDetails` shows the same details, with the same quick actions, on the page and in the session details sidebar; its `placement` decides whether it says why the Pull requests page does not list the pull request, and `PullRequestDetailContent` in `pr-details/index.tsx` takes it too, for the heading's level and size, whether it takes focus, whether the header and tab bar stick to the top of the sidebar's scroll, and the **Code** explorer's height.
  `PullRequestDetails` hands it the list entry and how to start a quick action, and `PullRequestDetailContent` derives the menu's quick actions from `actionFacts`.
  `PullRequestDetailContent` reads the pull request and its stack, and lays out the header, the tab bar, and the **Summary**, **Timeline**, and **Code** tabs, and the **Review draft** tab while the dashboard's status holds a draft of the pull request; its host holds the shown tab, and on the page `PullRequestDetailPage` takes **Code** from the route's `files` alone, so choosing it changes the address and the board's keys leave ↓ and ↑ to the explorer.
  It sends a resolve or unresolve through `useEditableRead`'s `edit`, shown at once, and a reply, comment, or description through its `write`, so the editor keeps its words until GitHub takes them; GitHub's refusal of a change shows once, above the **Summary** or **Timeline** tab.
  `pr-details/header.tsx` owns the crumbs, **Check out** menu, **Approve** button, primary control, title editor, author and branch rows, base freshness popover, stack menu, and linked-session list.
  `pr-details/checkout-menu.tsx` holds `CheckoutMenu`, which sends `PUT /api/pull-request/checkout` with the toasts of its progress and opens the session a worktree checkout started.
  `pr-details/use-condensed-header.ts` keeps each tab's condensed header state and its scroll thresholds, listening only to the details' own vertical scroller below the header, the same in the page and the sidebar; an issue's details key it by the issue instead of a tab.
  `summary.tsx` holds Reviewers, Labels, the description editor, Checks, and Comments; `section.tsx` provides its sticky collapsible headings, which read the details' scroller from its `DetailsScrollerContext` and keep a pinned heading in place as it collapses, through `sectionCollapseAnchorScrollTop` in `section.logic.ts`.
  `stack.tsx` holds `StackPopover`, which the header's **N/M** menu and a session header's pull request button both open: the stack on `StackRail`, on `web/components/rail.tsx`, its `MergeStack`, which queues the stack's merge through `MergePopover`, and the session's other pull requests.
  `checks.tsx` draws the tab bar's checks and popover, and the `Checks` list that the popover and **Summary**'s Checks share, and `code.tsx` the **Code** tab, keyed on the pull request.
  `pr-fields.tsx` holds the **Summary**'s reviewers and labels pickers and the save and send callbacks; a table row's or card's review cell uses the same reviewers picker.
  `pr-details/comments.tsx` draws Summary conversation cards, filters, sort, paging, resolve, and reply composers; Cmd+Enter uses `isSubmitChord` from `web/components/form-dialog.tsx`.
  `pr-details/composer.tsx` is `PullRequestComposer`, the details' floating button and popover with **Comment**, **Close with comment** or **Reopen with comment**, and **Review (N)**, which submits an open Review draft through `PUT /api/review-draft/post` with its `submit`, or sends a `review` change; it keeps both forms' text while the popover is closed, and `composer.logic.ts` holds which verdicts it offers, its button's label, and the summary's placeholder.
  `pr-markdown.tsx` scopes GitHub alerts, autolinks, inline code, attachment cards, and proxied media to PR bodies and comments, over `rehypePullRequestMarkdown` in `pr-markdown.logic.ts`, one pass over the sanitized tree, as a `MarkdownPreset` it builds on `message-markdown.tsx`'s `GITHUB_PRESET`.
  `pr-timeline.tsx` is the **Timeline**: comments, commits, reviews, every nonempty thread, and known lifecycle events on T3's rail, with local reply disclosures, read-only reactions, a sort toggle, and the **New** line from the last visit it keeps in localStorage.
  `web/pull-request-timeline.ts` interleaves activity before grouping adjacent comments, with one row per commit; the unread boundary splits groups in either sort order.
  Its review rows say whether the verdict came before the newest commit, and `approvalCount` counts the reviewers whose latest verdict approves the newest commit, as T3 does.
  `pr-details/message.tsx` holds what **Summary** and the **Timeline** both draw: each review state's label and colors, and a thread's `path:line` link.
  `pr-row.tsx` draws the sidebar row, the table row, and the board's card, each with `ReviewDraftTag` while a review draft waits to post, over the props they share, `RowBase`, and exports the DOM lookups of a row and its link that the board's keys use; a card's **Merge** badge takes its confirmation's open state from the board, so a drop on **Recently merged** opens it.
  The table row's and card's review cell, `ReviewPicker`, asks for reviews or withdraws them, and each row and card opens its `⋯` menu's items on right-click through `RowContextMenu`; both read the repository's people through one `usePullRequestOptions`, when either first opens.
  Both send review requests through `useReviewRequests`, which shows each pick at once and sends them to GitHub one after another, apart from the row's state changes, which take one at a time.
  `pr-details/review-draft.tsx` is the **Review draft** tab, `ReviewDraftPanel`: the verdict, the summary, each finding with **Accept**, **Dismiss**, and **Edit**, which send `review-draft` socket messages, the **Preview** from `GET /api/review-draft/preview`, and **Post review**, a confirmation that posts through `PUT /api/review-draft/post`.
  `pr-menu.tsx` holds `PullRequestMenu`, the shared row and header `⋯` menu, whose items, `PullRequestMenuItems`, a row's right-click menu lists too: quick actions, **Rebase on** the base, merge method radios, **Approve** where its caller passes `onApprove`, state changes, a row's **Reviewers** submenu, host links, clipboard actions, and inline-confirmed close or reopen.
  Its **Rebase on** item and the page's **Rebase N behind** button queue rebases in `web/pull-request-rebases.ts`, which sends `PUT /api/pull-request/rebase` one pull request at a time, skips the stack above one that stopped until the queue empties, whichever click queued it, toasts each outcome and a bulk run's sum, and hands a conflict to **Resolve conflicts** through the hooks its caller passes, which stay those of the page that queued it.
  `rebaseApplies` in `web/pull-requests-model.ts` decides which pull requests offer the item, and `rebaseOrder` which ones the button rebases in one repository, the bottom of each stack first, by the same walk down the stack, `chainBelow`, that keeps a stack's rows together; `usePullRequests` holds both callbacks.
  `web/use-inline-confirm.ts` arms one action for three seconds and disarms on Escape, blur, or an outside pointer press.
  `web/components/copyable-code.tsx` copies a command or branch and briefly swaps its label to **Copied**.
  `merge-popover.tsx` keeps the popover confirmation for rows, the bell, and a session's stack.
  It and the header's inline confirmation share `use-merge-controller.ts`: `useMergeController` owns the method, the queued merge lookup, the head-pinned request through `writeMergeQueue` in `web/reads.ts`, cancellation, and pending state, and remembers the method only when a merge is confirmed.
  Its `queuedMergeText` words the status and `QueuedMergeNote` offers Cancel or Dismiss through `useCancelMerge`.
  `web/use-drag-order.ts` drags the pull request list's repositories, sections, and pull requests, each within its own scope, and draws the drop line; `web/use-pointer-drag.ts` turns a mouse or pen press into a drag past a few pixels, scrolls its scroller near the edges, cancels on Esc, and swallows the click its release makes.
  The Pull requests page uses `web/components/list-page.tsx` for its frame, header, and load and refresh states through `ListPage`, the tickets and Email pages its `PolledPageFrame` and `PolledContent`, and the Todo and Calendar pages, the New Bot form, and a Bot's routines card and routine editor its `PageFrame`.
  `PolledPageFrame` renders ordinary children while reads load; only `PolledContent` supplies a data render callback, after an answer exists.
  `web/components/list-split.tsx` holds `ListSplit`, the Todo, Email, and tickets pages' list on the left and their open item on the right, split by a line you drag to size the list, at a width each page stores in localStorage under its own key; a page too narrow for both shows one or the other.
  It also owns `DetailBar` and `BarAction`, the narrow sticky bar the Todo, Email, and tickets pages put on top of their open item, with the previous, next, and close controls, and a slot for the page's own actions.
  The pull request's and the issue's details use `web/components/sheet-details.tsx` for the sections, links, comments, and `MetaRow`, the icon-and-label field row, of those details.
  `LoadNote` is the loading or error line that the pull request's details, the issue's, the conversation's, and the list page share.
  `web/components/fold.tsx` holds the fold button that the Pull requests and tickets pages share, `useFolds`, which keeps in localStorage the sections you flipped from their default fold, and `useReveal`, which unfolds a section or a row and scrolls to it once that element is in the document; `web/section.ts` names such a section target.
  The Pull requests page binds ↓, ↑, O, E, and `.` through `usePullRequestKeys`, over the pull requests that `shownPullRequests` in `web/pull-requests-model.ts` lists in order, or `shownBoardPullRequests` on the board, so a folded section's or column's rows drop out, binds Alt+Shift+↑ and ↓ to move the focused heading or row by its `data-move` attribute, and on the board binds Space to pick up the focused card.
- `web/assets.d.ts`: the module type of the PDF.js worker's URL, which the page imports as an asset.
- `web/components/ui`, `web/lib`, and `web/hooks`: files from the Fluid registry, and `web/components/kibo-ui` from Kibo UI's; `web/components/ui/PATCHES.md` lists every change the dashboard makes to them.
  The sidebar's parts are split over `sidebar.tsx`, `sidebar-core.tsx`, `sidebar-group.tsx`, `sidebar-slot.tsx`, `sidebar-menu.tsx`, `sidebar-menu-scope.tsx`, and `sidebar-menu-row.ts`, and the composer's over `input-message.tsx`, `file-preview-tile.tsx`, `web/hooks/use-region-height.ts`, and `web/hooks/use-is-touch.ts`.
