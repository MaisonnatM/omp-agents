# Starter kit and docs

`templates/omp/` holds the omp starter kit and its installer, `templates/omp/install.ts` (`bun run omp-template`).
Its `agent/` files are the default kit.
The installer's `planStarterKit` reads the same file, setting, marketplace, and plugin requirements for installation and Get started; customized `keep` entries count as present.
The dashboard supplies read-only native snapshots instead of running CLI config initialization, and installation uses the exact resolved omp command, including `OMP_PACKAGE_DIR`.
Packaged resources include `agent/`, `config.yml`, and `install.js`.
`templates/omp/README.md` lists what each of its extensions does.
`agent/extensions/google-accounts.ts` tells a session which Google account each Gmail and Google Calendar MCP server signs in as, and which addresses its workspace links; `templates/omp/google-accounts.test.ts` tests its workspace lookup against a real repository and a linked worktree outside it, and its prompt text, and `templates/omp/extensions.test.ts` runs its hook on scratch files.
`agent/extensions/headless-mark.ts` records in an `omp-agents.headless` entry whether `omp -p` or `--mode json` started the session, at each start that changes it, which `src/session-facts.ts` folds and `SessionFiles.past` drops; `templates/omp/extensions.test.ts` runs its hook through starts in each mode.
`agent/extensions/request-log.ts` both records each provider request and, run with Bun, rebuilds the requests a session file records and checks their hashes; `templates/omp/request-log.test.ts` records requests through omp's own blob store and checks every rebuilt body against the one sent.
`agent/extensions/land.ts` registers the `land` tool and its bash gate; `agent/extensions/land/lander.ts` holds the landing itself, which reads `.omp/land.json`, merges in a temporary worktree, runs the checks under their silence and total limits, pushes, and moves the local target forward, and `land/gate.ts` holds `bypass`, which decides whether a git or gh command reaches the target.
`templates/omp/land.test.ts` lands real branches through a bare remote: a clean landing, a failing, a flaky, and a silent check, a conflict, a target that moves during the checks, and refusals, and checks the gate on pushes, merges, and `gh pr merge`.
[`.omp/land.json`](../../.omp/land.json) lists this repository's own landing checks, the ones its pre-push hook runs, plus the CHANGELOG rule.
`agent/extensions/session-trailer.ts` adds a config-based `prepare-commit-msg` git hook to omp's environment through `GIT_CONFIG_PARAMETERS`, once, which writes an `Omp-Session: <PI_SESSION_ID>` trailer on every commit a session makes; `templates/omp/session-trailer.test.ts` makes real commits with and without a session id.
`agent/skills/ship/SKILL.md` holds the `/ship` procedure and names `workflow` in its frontmatter's `metadata.tags`, so Settings › Workflows lists it; `agent/commands/ship.md` only tells the session to follow that skill for its argument, so `/ship <issue>` still starts the workflow and `src/task-claims.ts` still reads the issue from it.
`agent/extensions/ship.ts` gates draft PRs and putting a PR live on bash commands that `agent/extensions/shell/commands.ts` splits into words outside quotes, past `NAME=value` assignments and `env` prefixes, and that its `located` places in the directory each runs in.
`templates/omp/ship.test.ts` tests that parsing, the `gh pr view` selector it builds from a `gh pr ready`, including a `-R` given before `ready`, and the owner check `tool_result` uses before it marks the tracked PR live.
It also tests `reviewNeeded` for each review in `REVIEWS`: the thermonuclear review is needed when the checkout has no `.omp/review-paths`, and the interface review only when it has `.omp/ui-paths`; with the file, either is needed when GitHub lists fewer changed files than the PR has, or when a changed file matches one of its globs.
Then `publishBlocker` requires the checkbox of each needed review, interface first, and always forbids an unchecked `- [ ] Browser proof` box, and `authDiagnosis` names the GitHub credential that GitHub rejects without printing its token.
`agent/agents/interface-reviewer.md` is the read-only agent the `/ship` Interface review stage spawns; it runs the user's `interface-review` skill, which the kit does not ship, and stops naming the skill when it or `better-interface` is missing, then applies the autoloaded `app-consistency-review` skill.
`agent/skills/app-consistency-review/SKILL.md` checks a PR's interface changes against the app's shared components, tokens, and sibling screens, and lists every new pattern.
`agent/extensions/pr-description.ts` registers the essential `pr_description` tool and refuses direct shell body writes that skip its checked read, private original backup, empty-output and replacement-anchor checks, and fresh preflight comparison.
`agent/extensions/github/description.ts` owns that edit transaction, and `github/owner-lock.ts` is the common ownership primitive.
`github/access.ts` keeps only each budget's quota cooldown on disk, a `{ resetAt }` file per budget, read without a lock and extended under a short `OwnerLock`, so a GraphQL or REST budget that one dashboard or CLI process found exhausted fails fast in every other process until its reset; it keeps no answers, which callers cache in memory.
Only a failed command is classified, so a successful answer that mentions rate limits stays data; an exhausted budget pauses until the reset `gh api rate_limit` reports when that budget's `remaining` is 0, else for a minute.
`github/command.ts` holds `CommandError`, the failed command whose `answer` is its stdout parsed as JSON, which `runJson` in `src/proc.ts` also throws, and `ghText` and `ghJson`.
`github/runner.ts` holds `GhRunner`, which `ship.ts` and `pr-description.ts` run `gh` through under those cooldowns; after a 401, when `gh auth status` shows an environment token such as a project `.env`'s `GITHUB_TOKEN` rejected ahead of a stored login that works, it runs gh as `env -u` that variable from then on and keys its cooldowns with `cooldownDirectory` on the stored login, which the dashboard shares.
`agent/extensions/worktree-guard.ts` keeps sessions from changing a checkout under each other: a claim file in each checkout's git dir names the omp process that owns it, and the HEAD each process last left there lives on `globalThis`, which every session and subagent of that process shares; it classifies git, gt, and `gh pr checkout` commands, with the directory `located` in `shell/commands.ts` gives each, looking through wrappers such as `env`, whose `-C` it follows, and into `bash -c` scripts, and asks the user before an edit of a file git ignores in a main checkout on its default branch.
`templates/omp/extensions.test.ts` runs its hooks on scratch repositories: another live session's claim on a checkout or a linked worktree, claims of ended processes, a branch switched by another process and a switch git refused, the session's own switches, a subagent, shutdown, and the directories `cd`, `env -C`, `git -C`, `--cwd`, and `bash -c` name; for `ship.ts` it checks that a publish reads the PR and review paths in the checkout it runs in, and is refused from another repository's checkout or an unlocated directory.
`agent/skills/decision-records/SKILL.md` tells agents to record each choice as one dated file in a project's `docs/decisions/`, and its `check.ts` (`bun check.ts [directory]`) checks each record's file name, frontmatter, title, and `supersedes` links; `src/docs.test.ts` runs it on this repository's `docs/decisions/`.
`maintainer/` is the maintainer git profile, `AGENTS.md`, `templates/omp/maintainer/docs/git-workflow.md`, the `mma-mode` and `best-in-class-approach` skills, and `templates/omp/maintainer/scripts/prune-git-branches.py` and `templates/omp/maintainer/scripts/session-speed.py`, copied only when you pass `--maintainer`, and a file there replaces the `agent/` file with the same path.
[Template sync](../../CODING_STANDARDS.md#template-sync) says how to copy an edited live file back.
The default `agent/AGENTS.md` keeps worktree and force-push safety inline and links to the model and review references under `agent/docs/`.
The profile's `templates/omp/maintainer/docs/git-workflow.md` detects Graphite with `git rev-parse --path-format=absolute --git-common-dir`, so the same procedure works from a checkout, a linked worktree, or a nested directory.
The repository's agent guide links to the [coding standards](../../CODING_STANDARDS.md), which every contributor follows, and to [agent smoke checks](../agent-smoke.md) for server authentication and lifecycle, browser verification, and desktop verification.
It also links [decisions](../decisions/), one file per design choice and why it was made, [`LEARNINGS.md`](../../LEARNINGS.md), pitfalls agents hit here, and [`GLOSSARY.md`](../../GLOSSARY.md), the project's vocabulary.
[`CHANGELOG.md`](../../CHANGELOG.md) holds what each change to `main` did, in everyday words, as the header's What's new lists it; [Changelog](../../CODING_STANDARDS.md#changelog) says how to write it, and `.gitattributes` merges it with git's union driver so two branches' lines never conflict.
[`.omp/review-paths`](../../.omp/review-paths) lists, one glob per line, this repository's shared contracts and central files; a PR that changes one needs the thermonuclear review, and `agent/extensions/ship.ts` reads the file from the checkout to decide whether the publish gate asks for the review checkbox.
[`.omp/ui-paths`](../../.omp/ui-paths) lists the page's components and styles the same way; a PR that changes one needs the interface review, and without the file `ship.ts` never asks for it.
[Getting started](../getting-started.md) walks a new user through a first session and each integration's sign-in, and lists what a new computer needs beyond the starter kit and Settings sync; `docs/images/` holds the README's screenshot.
`docs/usage.md`, `docs/architecture.md`, and `docs/code-layout.md` are indexes, one line per file in `docs/usage/`, `docs/architecture/`, and `docs/code-layout/`, so an agent reads only the feature it needs; `src/docs.test.ts` fails a doc over 32 KiB.
`patches/omp-18.12.3-paid-cursor-fallback.patch` preserves the external OMP runtime's paid Cursor fallback implementation and regression tests against upstream `v18.12.3`.
It is not loaded or applied by the dashboard; [omp modules](../architecture/omp-modules.md) describes its base, application, and installation boundary.
`scripts/omp-release.ts` (`bun run omp-release [version]`) checks an omp release against this codebase: it installs that release and the tested one, runs `src/omp/modules.ts` and `bun test` against the release, and writes a report of the test result, the omp files that changed between the two, and their changelogs to `node_modules/.cache/`.
`.agents/skills/omp-release/SKILL.md` is the skill an agent follows to sort that report into what must change, what to adopt, and docs drift, and to open the version bump when only the pins must change.
`scripts/activity-reconcile.ts` (`bun scripts/activity-reconcile.ts --url <address> --token <token> [--agent]`) drives a running dashboard through a fixed script and checks Settings › Activity counted exactly it; `scripts/activity-bench.ts` (`--rows <n> --runs <n>`) times the activity store; see [Agent smoke checks](../agent-smoke.md#activity-reconcile).
