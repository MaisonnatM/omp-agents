# Server: shared types, omp facades, analytics, and subprocesses

- `src/shared/`: every type that crosses the socket or the HTTP API, one file per domain.
  Each answer a polled store keeps in localStorage has its decoder beside its type: `decodePullRequestList`, `decodeTicketsAnswer`, `decodeIntegrationsAnswer`, `decodeAnalytics`, `decodeGoogleStatus`, `decodeCalendarEventsAnswer`, `decodeLocalEventsAnswer`, and `decodeEmailAnswer`, which check every field of the type.
  `protocol.ts` holds `ServerMsg` and `ClientMsg`; `sessions.ts` the roster and past rows (`RosterHost`, `PastSession`), views, user requests, and starts; `transcript.ts` the transcript items, changed files, and images; `github.ts` the pull request and pull request list shapes; `tickets.ts` the Linear issues; `accounts.ts` the MCP integrations and their OAuth client setups; `calendar.ts` the Google calendars, their events, a new event, and the events kept on this computer; `git.ts` the checkouts and branches; `models.ts` the models, routing, plan usage, and omp's files; `notices.ts` the bell's notices; and `analytics.ts` the Analytics section.
  `accounts.ts` also holds `AccountId`, `GoogleAccount`, the `accounts` column of `MCP_SERVICES`, and `visibleAccounts`, the Google accounts a workspace shows: those linked to it and those linked to none.
  `transcript.ts` also holds `isDashboardPrompt`, which tells a prompt the dashboard sent in the user's place, which the page hides.
  Every place that shows a prompt's text checks it: the transcript and its starting prompt in `src/transcript.ts`, the **Trajectory** in `src/trajectory.ts`, the queued rows and ↑ in `web/components/composer-queue.tsx`, the live title's `/rename` in `src/dashboard-session.ts`, and the past title in `src/omp/sessions.ts`; a new place that shows prompt text needs the same check.
  `transcript.ts` also holds `MEDIA_FILE_TYPES` and `mediaUrl`, the `GET /api/media` address of an image or video on this computer, which the media tree and the page both build.
  `mcp-servers.ts` holds the rows and bodies of Settings › MCP servers, and `mcp-catalog.ts` the catalog of remote servers it offers.
  `mcp-status.ts` holds `McpRemoteStatus` and `McpTool`, where omp stands with a remote MCP server, which an integration's `McpConnection` in `accounts.ts` and a server's `McpServerStatus` in `mcp-servers.ts` both build on.
  `gmail.ts` holds `MailThread` and `EmailAnswer`, the Email page's conversations, and `ThreadAnswer` with its `MailMessage`, `MailPerson`, `MailBody`, and `MailAttachment`, one conversation in full.
  `newSessionRequest` in `sessions.ts` builds a new-session start with every option not given defaulted, for the socket's parser, the routine runner, and their tests.
  `SessionFacts` in `sessions.ts` declares a session's pull requests, Linear issues, /ship stage, worktree, and branch once, and `RosterHost` and `PastSession` extend it.
  `parseNewSessionRequest` there checks one, with `parseImages`, `parseModel`, `parseThinking`, and `parseSkill`, for the socket's `start` and a start kept in `scheduled.json`; `parsePullRequest` in `github.ts` checks a pull request's owner, repository, and number.
  The routine shapes (`Routine`, `RoutineRun`, `RoutineChange`) live in `src/routines.ts`, which the socket messages import.
  `selectorOf` names a model as `provider/id`, which both session transports and the model picker use, and `pullRequestUrl` a pull request's GitHub page, which the server's prompts and the page's links share.
  `prompt-files.ts` holds the files a prompt carries as text: `withFiles` and `splitFiles`, which put them after the typed text and take them back off, `plainText`, which tells a text file, and the limits and body of `PUT /api/attachment/document`.
  `session-visuals.ts` holds the `mermaid` and `chart` fences' rules, `mermaidKind` and `parseChartSpec` with their limits, which the page checks a fence with and the session visuals extension tells the model.
  `discussions.ts` holds **Ask about this**'s request, its events, the limits `parseDiscussionRequest` in `src/server/wire.ts` holds it to, `discussionPrompt`, the one message the model gets, and `sessionMessage`, what **Send to session** sends.
  `processes.ts` holds a live session's `SessionProcesses`, the `LiveSessionProcesses` list entry that adds its instance id, the `ProcessStop` request, and `ProcessSettings` with its choices and `parseProcessSettings`.
- `src/omp/`: the facades over omp's modules: `modules.ts` loads them, `install.ts` finds the package and its CLI and reads its `package.json` with `readManifest`, and `collab.ts`, `rpc.ts`, `sessions.ts`, `stats.ts`, `config.ts`, `discovery.ts`, `mcp.ts`, `models.ts`, `model-updates.ts`, `release.ts`, `prompts.ts`, `documents.ts`, `isolation.ts`, `turn-failure.ts`, and `daemons.ts`, the daemon brokers' services and the stop of one, wrap one area each.
  `context-index.ts` keeps the context-source index beside omp-stats' database: each request of each session file split by source, re-read only for files that changed.
  `discussion.ts` holds `answerDiscussion`, one streamed model call on omp's `smol` role, else `default`, that answers **Ask about this** outside every session.
  `session-visuals-extension.ts` is the omp extension, loaded with `-e`, that appends the two visual fence formats to the system prompt of a session the dashboard starts, resumes, or forks; `sessionVisualsExtension` in `src/server/resources.ts` names its file, a bundle beside `server.js` in the packaged app.
  `replay-fork.ts` owns native replay prompt reading, ancestry and request correlation, original evidence blobs, repairs, and fork writes; it returns plain replay data and narrow fork and close operations.
- `src/activity.ts`: `foldActivity`, which folds the stored activity rows into Settings › Activity's uses, last uses, moves between views, time on each view, and days; `src/shared/activity.ts` holds the event kinds, the key pattern, `CONTROLS`, `ACTION_MESSAGES`, and the answer's decoder.
- `src/analytics.ts`: merges Claude Code's and Codex's requests into omp-stats' `StatsRead` with `withForeignUsage`, then folds per-file rows into sessions and workspaces.
  It joins each saved session's `SessionSummary`, its title and working directory, without reading transcripts.
- `src/context-sources.ts`: splits a request's input by source, from its context messages and a subagent's recorded system prompt, and folds the index's rows into the Analytics tab's context-source report.
- `src/proc.ts` runs subprocesses with the environment as this process holds it then, and `runShell` a routine's shell command, `src/json.ts` narrows untyped JSON (`isObject`, `isNonEmpty`, `isSafeInteger`, `isDay`, `str`, `oneOf`, `isTexts`, `errorText`), `src/fs.ts` replaces a file through a temporary one beside it and holds `JsonFile`, the load/save store behind `interrupted.json`, `todos.json`, `routines.json`, `scheduled.json`, `workspaces.json`, `pins.json`, `processes.json`, `calendars.json`, `google-accounts.json`, `events.json`, `review-drafts.json`, `notices.json`, and `settings-sync.json`.
  `childEnv` in `src/proc.ts` is that environment without the server's own `PORT` and `OMP_AGENTS_PARENT`, which the omp sessions, the terminal panel's shells, routine commands, and a `run` with `child: true`, such as a pull request rebase's git hooks, get, so a server an agent starts neither takes the dashboard's port nor exits when its stdin ends.
  A `JsonFile`'s `save` writes once per event-loop turn however many changes arrive in it, and `flushJsonFiles` retries every dirty value as the server stops or exits.
  `flush` reports success and retains a failed write for a later retry.
  `ReducerFile` wraps `JsonFile` for reducer-backed lists, loads the value or an empty one, and saves only when a change gives a new value.
  Settings sync reads and replaces one whole through `json`, the value as its file holds it, `parse`, the file's own parser, and `replace`.
  A `shared` reducer holds `templates/omp/agent/extensions/github/owner-lock.ts`'s `OwnerLock` at `<path>.lock` across reload, reduction, and immediate persistence.
  A failed shared write rejects its caller and retains both the dirty value and ownership until a successful retry.
  `src/owner-lock.test.ts` covers ownership and takeover; `src/fs.test.ts` also races real processes over shared updates and scheduled claims.
  `atomicWriteTextSync` also preserves private permissions when task ownership replaces `task-claims.json`.
  `src/json.ts` also holds `Parsed<T>`, the `{ ok }` or refusal every parser returns, and `BASE64`, which the socket's parsers and the domain parsers share.
  `src/paths.ts` names these files beside the access token, the old `google.json` the server deletes, the old `projects.json` an older version kept the workspaces in (`oldWorkspacesFile`), and, under the data directory, the settings sync's repository (`settingsSyncRepo`).
  `src/json.ts` also composes guards of whole shapes (`fields`, `tagged`, `arrayOf`, `nullable`), which `decoder` turns into decoders.
