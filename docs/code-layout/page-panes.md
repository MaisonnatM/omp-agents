# Page: panes, session details, and changes

- `web/components/pane.tsx`: a pane, whose view renders inside a `RenderBoundary` from `web/components/render-boundary.tsx`, so a view that throws shows its error in that pane and the rest of the page stays; `web/app.tsx` puts one around the page too, and both clear when the hash names another view.
  `ViewConversation` there puts the road-icon trajectory toggle after the session's title.
  `conversation.tsx` holds the live composer, `conversation-header.tsx` its header with the End session button, which for a private session shows a lock and asks for a second click, `past-conversation.tsx` a past session's view, which for a Claude Code or Codex session reads `Read-only · <agent>` and offers neither **Resume** nor fork buttons, and `transcript.tsx` the transcript, whose `task` rows link to their subagents.
  `session-title.tsx` is `SessionTitle`, the title both session headers show for a session that can be renamed, a session this dashboard runs or a saved omp session, which a click turns into a field: Enter or leaving it sends `rename-session`, Escape cancels, and focus returns to the title.
  `subject.ts` is `subjectOf`, the one place that tells a session from a subagent and derives what the composer may do, and `deliveryOf`, how a message goes now; `model-slot.tsx` is the model and thinking switch, and `session-meta.tsx` a session header's trail, `SessionIdCopy`, the copy-ID button both session headers put right after the title, and `SessionMeta`, the controls both session headers share: its branch, which copies the branch name and then calls `releaseBranch`, its ticket menu, and its pull request button, which opens `StackPopover` from `pull-requests/pr-details/stack.tsx`.
  `session-goal.tsx` holds the goal pill, its popover, and `GoalDialog`; `App` owns the dialog state and its `editGoal` action, shared by the header and the focused-session command in `shortcuts.ts` and `use-page-shortcuts.ts`.
  `context-ring.tsx` holds the terminal session's read-only meter and the dashboard session's context menu.
  `composer.tsx` holds `blockedShortcut`, `ComposerNote`, and `EmptyConversation`, which the new-session draft and the pages share, and `page-header.tsx` the `Header` every page uses, which shows the controls after its title only while the pointer is over the title or one of them has focus, and always on a touch screen.
  Below `sm`, the `Header` keeps its title's full width and wraps its buttons to a right-aligned row under it; see [Wrap the page header's controls under the title on a phone](../decisions/2026-11-08-wrap-the-page-header-controls-under-the-title-on-a-phone.md).
  `composer-queue.tsx` holds the queued rows and `useQueue`, and `composer-suggestions.tsx` the suggested prompts and their keys; `InputMessage` renders them through its `beforeEditor` and `afterActions` slots.
  `user-request.tsx` shows the open question above the composer through `question-card.tsx`, and binds its number keys while its pane is focused; the card itself handles only its own clicks and keys.
  `prompt-attachments.tsx` holds the composer's attached files, which the new-session draft shares: it reads each as an image, as text, or as a document omp converts, and sends a prompt's text files after its text and its images apart.
  `web/prompt-attachments-model.ts` holds `preparePrompt`, the one rule for which attached files a prompt carries: the composer runs it as files attach to drop what stays out, and again on the files it sends, so a file refused while it still converts never reaches a prompt.
  `composer-dictation.tsx` holds `useDictation`, one composer's view of the page's capture, its microphone `DictationButton` with the setup popover, and `DictationRow`, the status row above the text field; the live and new-session composers mount them for a composer that keeps a draft.
- `web/components/dashboard-context.tsx`: two contexts that `App` provides and the sidebar, the panes, and the pages read instead of taking props: the actions (`send`, `open`, `start`, `end`, …), which keep one identity for the page's life, and the status, which holds the connection, the last start of each kind, and `pullRequestsScope`; a component that reads only the actions never renders for a change of the status.
  `MentionListsContext` carries the lists of the composer's `@` menu apart from both, and `UserTodosContext` the todo list, which a sent prompt's todo chip reads to find the list that holds its todo now.
  `PersonalContext` carries where personal sessions run, `null` until the server says, for every place that names a workspace to call it **Personal**.
- `web/components/details-sidebar-frame.tsx`: `DetailsSidebarFrame`, the right sidebar's shell that a session's details and a Bot's share: a `FileBaseContext` of the focused session's directory so relative paths link, the stored tab, resolved against the tabs each render so a tab that appears later takes the stored choice, and the header of counted tabs over their panels, icons alone while five crowd a narrow sidebar.
  `DetailsEmpty` there is every tab's empty state, shadcn's `Empty` from `web/components/ui/empty.tsx` with the tab's icon.
  A tab that `scrollsItself`, as the PRs and Tickets tabs do, gets a plain panel of the sidebar's full height instead of the scroll area, so its content can keep a header above its own scroller.
  A tab that `keepMounted`, as the Browser does, stays mounted once first shown and is only hidden behind another tab, so the page in its `<webview>` survives the switch.
- `web/components/session-details.tsx`: the right sidebar's tabs for the focused pane, **PRs** in `session-pull-requests-tab.tsx`, for a session with any, **Browser**, `BrowserPanel` from `browser-panel.tsx`, in the desktop app for a live session or subagent, **Tickets** in `session-tickets-tab.tsx`, and **Memory** for a personal session, its facts in `MemoryList` from `memory-list.tsx`.
  `sessionWorkTabs` builds those tabs from a session's pull requests, its live view, and its Linear issues, and `ticketsTabs` there builds the **Tickets** tab alone, which a Bot's details in `web/components/bots/bot-details.tsx` show after its **Details** tab.
  `BrowserPanel` holds the Browser's tabs, Radix tabs that `BrowserTabStrip` draws as a web browser's: the session's **App** and one per page of the last **Review visuals** click, each a `BrowserPage` kept mounted while hidden; only the **App** tab saves the address it opens on next time.
  The default is **PRs**; a stored choice of the removed Todos, Files, Media, or Processes tab falls back to it.
  Each pull request shows through `PullRequestDetails` from `web/components/pull-requests/pr-page.tsx`, whose `session` lists the others under the **Stack** and whose `onPick` shows another pull request of the stack or the session in place of changing the address.
  Each Linear issue shows through `TicketDetailContent` from `web/components/tickets/ticket-details.tsx` with `placement="sidebar"`, one column that leaves focus where it is, with a row of identifiers above it to pick another; its `onPick` shows the parent or a sub-issue in place, and it draws the sub-issues on the stack's rail, `web/components/rail.tsx`.
- `web/components/transcript-minimap.tsx`: `TranscriptMinimap`, the rail of one line per turn on a transcript's left edge, after Notra's Chat Minimap, on `HoverCard` and `Tooltip` from `web/components/ui/`; it shows from two turns on, where its `MessageScroller`'s container query leaves room beside the messages, scrolls its own transcript's viewport to a turn's prompt, and lights the turn whose prompt last crossed the reading line.
- `web/components/session-todos-card.tsx`: `SessionTodosCard`, the **Todos** card that `Transcript` mounts before its `MessageScroller`, in the `[data-conversation]` wrapper, as one strip that opens the card's sections over the messages in a `Popover`: the ship stepper, the todo list, the `todos` of the transcript's `transcriptModel` in `web/transcript-view.ts`, then the **Subagents** section of `todos-card-subagents.tsx`, then the sections of `todos-card-changes.tsx`, each shown only with items.
  The whole card shows only while **Show todos card** is on, the preference `useTodosCardShown` reads, which Settings › Preferences and `TodosCardToggle`, the checklist toggle that `conversation-header.tsx` puts between **Open PR** and End session and `past-conversation.tsx` before **Resume**, both toggle.
  The card counts itself in `filledCards`, a keyed store by the view's hash, while it is mounted with a section to show, whether or not the preference hides it, and the toggle renders only while that count is above zero, so it leaves with the card when the trajectory unmounts the transcript.
  It renders nothing while no section shows.
  The strip's words come from `stripSummary` in `web/todos-strip-model.ts`; `StripLine` measures the line and shows each count whole or not at all, dropping them from the last one while the lead would get less than its own width or 12rem, whichever is less.
  The overlay is as wide as the strip and as tall as the wrapper leaves under it, so it never covers the composer; it is open for one view's hash at a time, and the file and image dialogs its sections open render inside it, so it stays open under them.
  The todo list and the ship stepper start unfolded, and whether each shows every step is kept in localStorage for every transcript.
- `web/components/todos-card-changes.tsx`: `useChanges`, the view's changed files, images, and sources, leaving out the session's own pull requests and Linear issues, and `ChangesSections`, the Todos card's **Files**, **Images**, and **Sources** sections with **Review** and the dialogs a file opens; `Transcript` passes the card its `changes` only while `ActivityShown` is on, and the folded sections stay under the `omp-agents.changes-card-closed` key from before the sections moved into the card.
  `ChangesSection` there is the folding header and body each of the card's sections under the todo list shares.
- `web/components/todos-card-subagents.tsx`: `SubagentsSection`, the Todos card's **Subagents** section, one row per subagent from `subagentTree` in `web/todos-card-subagents-model.ts`, indented by depth, each a link to the subagent's view with its status dot, type, and activity, and the stop button of a running one; its fold stays under `omp-agents.todos-card-subagents-closed`.
  The card computes the rows from the `subagents` that `Transcript` passes it from `SubagentLinks`, only while `ActivityShown` is on; a subagent's view lists only its own descendants.
- `web/components/subagent-links.tsx`: `SubagentLinks`, the context through which `ViewConversation` in `pane.tsx` hands a live view's transcript the session's subagents, the page's open, and the cancel, `null` in a past session, and `CancelAgentButton`, the stop button after a running subagent's link in a `task` row and in the Todos card.
- `web/components/prompt-history.tsx`: **Chat history**, after Kobra's Chat History: `PromptHistoryButton`, the live composer's button from two prompts on, which selects only the view's prompt count, and `PromptHistory`, which `Transcript` mounts in its `MessageScroller` and draws, while a keyed store by the view's hash holds it open, as a blurred layer with the turns of the transcript model's `outline` as one column of prompt bubbles; prompts in view slide from their measured place in the transcript, and a pick scrolls the viewport with the minimap's `scrollToMessage` and outlines the bubble.
- `web/components/changes/`: the session's changes dialog, `session-changes-dialog.tsx`, in its frame, `explorer-dialog.tsx`, with its explorer and editor, `changes-explorer.tsx`, the explorer's tree, `file-tree.tsx`, the Diff view's list of every file's diff, read as each nears the view, `diff-stack.tsx`, and one file's diff and File views, `code-view.tsx`.
  `use-file-cursor.ts` holds the file an explorer marks, which ↓ and ↑ step through; the explorer and a pull request's **Code** tab, `web/components/pull-requests/pr-details/code-files.tsx`, each lay out `FileTree` and `DiffStack` around it.
  `web/components/line-counts.tsx` draws the lines added and removed, `+12 −3`, that the changes dialog and the Todos card share.
  `web/diff-options.ts` holds shared diff preferences and the whitespace-only replacement transform.
  The changes dialog's explorer orders the files as its tree does; the **Code** tab keeps the server's reading order and puts the tree at the right.
  Each of them holds which files `DiffStack` shows folded, through `useCollapsedFiles` there, so the **Code** tab folds them all at once or folds one marked viewed.
  `diff-review.ts` is the context a page reads its diffs through: the layout, wrapping, and whitespace it chose, the box it shows under picked lines, which the Code tab fills with `web/components/pull-requests/pr-details/diff-controls.tsx`, and the end of each file's header, which it fills with the Viewed checkbox from `viewed-files.tsx` beside it; the changes dialog takes the defaults and picks no lines.
