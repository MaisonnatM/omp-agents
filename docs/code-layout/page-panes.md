# Page: panes, session details, and changes

- `web/components/pane.tsx`: a pane, whose view renders inside a `RenderBoundary` from `web/components/render-boundary.tsx`, so a view that throws shows its error in that pane and the rest of the page stays; `web/app.tsx` puts one around the page too, and both clear when the hash names another view.
  `ViewConversation` there puts the road-icon trajectory toggle after the session's title.
  `conversation.tsx` holds the live composer, `conversation-header.tsx` its header with the End session button, which for a private session shows a lock and asks for a second click, `past-conversation.tsx` a past session's view, which for a Claude Code or Codex session reads `Read-only · <agent>` and offers neither **Resume** nor fork buttons, and `transcript.tsx` the transcript.
  `session-title.tsx` is `SessionTitle`, the title both session headers show for a session that can be renamed, a session this dashboard runs or a saved omp session, which a click turns into a field: Enter or leaving it sends `rename-session`, Escape cancels, and focus returns to the title.
  `subject.ts` is `subjectOf`, the one place that tells a session from a subagent and derives what the composer may do, and `deliveryOf`, how a message goes now; `model-slot.tsx` is the model and thinking switch, and `session-meta.tsx` a session header's trail and `SessionIdCopy`, the copy-ID button both session headers put right after the title.
  `session-goal.tsx` holds the goal pill, its popover, and `GoalDialog`; `App` owns the dialog state and its `editGoal` action, shared by the header and the focused-session command in `shortcuts.ts` and `use-page-shortcuts.ts`.
  `context-ring.tsx` holds the terminal session's read-only meter and the dashboard session's context menu.
  `composer.tsx` holds `blockedShortcut`, `ComposerNote`, and `EmptyConversation`, which the new-session draft and the pages share, and `page-header.tsx` the `Header` every page uses, which shows the controls after its title only while the pointer is over the title or one of them has focus, and always on a touch screen.
  The `Header` keeps its title at least 16rem wide beside its buttons, or its full width when shorter, and otherwise wraps the buttons to a right-aligned row under it; see [The page header folds its buttons before it squeezes the title](../decisions/2026-11-12-the-page-header-folds-its-buttons-before-it-squeezes-the-title.md).
  `composer-queue.tsx` holds the queued rows and `useQueue`, and `composer-suggestions.tsx` the suggested prompts and their keys; `InputMessage` renders them through its `beforeEditor` and `afterActions` slots.
  `user-request.tsx` shows the open question above the composer through `question-card.tsx`, and binds its number keys while its pane is focused; the card itself handles only its own clicks and keys.
  `question-options.tsx` holds `QuestionOptions`, the card's pickable rows as one radio or checkbox group, with keyboard moves and a sliding hover highlight.
  `prompt-attachments.tsx` holds the composer's attached files, which the new-session draft shares: it reads each as an image, as text, or as a document omp converts, and sends a prompt's text files after its text and its images apart.
  `web/prompt-attachments-model.ts` holds `preparePrompt`, the one rule for which attached files a prompt carries: the composer runs it as files attach to drop what stays out, and again on the files it sends, so a file refused while it still converts never reaches a prompt.
  `composer-dictation.tsx` holds `useDictation`, one composer's view of the page's capture, its microphone `DictationButton` with the setup popover, and `DictationRow`, the status row above the text field; the live and new-session composers mount them for a composer that keeps a draft.
- `web/components/dashboard-context.tsx`: two contexts that `App` provides and the sidebar, the panes, and the pages read instead of taking props: the actions (`send`, `open`, `start`, `end`, …), which keep one identity for the page's life, and the status, which holds the connection, the last start of each kind, and `pullRequestsScope`; a component that reads only the actions never renders for a change of the status.
  `MentionListsContext` carries the lists of the composer's `@` menu apart from both, and `UserTodosContext` the todo list, which a sent prompt's todo chip reads to find the list that holds its todo now.
- `web/components/details-sidebar-frame.tsx`: `DetailsSidebarFrame`, the right sidebar's shell that a session's details and a Bot's share: a `FileBaseContext` of the focused session's directory so relative paths link, and UI SDK tabs whose row draws the first tab and the open ones, each a `ClosableTab` from `web/components/closable-tab.tsx` with its count as a `CountPill`, then a **+** menu of every tab, its picked one checked, and the view's own sections, over the open tab's panel.
  The open tabs live in localStorage through `web/details-tabs.ts`, whose `showDetailsTab` keeps the first tab out of the stored list; the frame resolves them against the tabs each render, so a tab that appears later comes back, and a tab's `shortcut` picks it only while the sidebar is open.
  `DetailsEmpty` there is every tab's empty state, shadcn's `Empty` from `web/components/ui/empty.tsx` with the tab's icon.
  A tab that `scrollsItself`, as the PRs tab does, gets a plain panel of the sidebar's full height instead of the scroll area, so its content can keep a header above its own scroller.
  A tab that `keepMounted`, as the Browser does, stays mounted once first shown and is only hidden behind another tab, so the page in its `<webview>` survives the switch.
- `web/components/session-details.tsx`: the right sidebar's tabs for the focused pane, **Overview**, `SessionOverview` from `session-overview.tsx`, the **Subagent** tab, `SubagentConversation`, which draws `ViewConversation` from `pane.tsx` for the subagent picked in **Overview** or the **+** menu and streams it through `useShowConversation`, **PRs** in `session-pull-requests-tab.tsx`, for a session with any, **Browser**, `BrowserPanel` from `browser-panel.tsx`, in the desktop app for a live session or subagent, and **Artifacts**, `ArtifactsPanel` from `artifacts-panel.tsx`, once the view saved one and its session id is known.
  `SessionDetails` wraps `useSubagentLinks`'s `onOpen` so a plain click picks the subagent for that tab, while a split or a new window opens it as before.
  `sessionWorkTabs` builds those tabs from a session's pull requests, its live view, its artifacts, the screen changes its latest reply lists, and the Linear issues it links; `useOpenTabOnNew` adds the **Review** tab once a reply lists a new change.
  `web/components/review-panel.tsx` is the **Review** tab: `ReviewPanel` picks one change in its toolbar, `Wipe` draws the before screenshot clipped over the after one with a slider line and numbered pins, and `ChangeReview` shows the description read-only for a past session, or `ChangeRequest` for a live one: the editable description, pin notes, and quick edit, which it appends to the composer with `appendToComposer`.
  `web/components/session-linear-tab.tsx` is the **Linear** tab, which `sessionWorkTabs` keeps mounted while another tab shows so a typed issue stays: `SessionLinearTab` reads the issue shown through `GET /api/linear/issue`, its field parsing an id or a link with `linearIssueId` from `src/shared/linear.ts`, over the issues `useLinkedIssues` in `web/pane-store.ts` lists.
  `useOpenTabOnNew` in `session-details.tsx` adds the **Linear** and **PRs** tabs behind the one on screen with `addDetailsTab` from `web/details-tabs.ts` when the session shown links an issue or a pull request, which `newIdsOnOpen` there tracks for the last session shown, so opening another session adds them again, while a subagent's view of the same session or a transcript that loads again adds them no second time; the **Review** tab's `newIdsByScope` tracks each session for the page's life instead.
  `useSessionWork` there gathers what those tabs show, the pull requests, Linear issues, artifacts, and screen changes, and runs those openers from a `workTabOpeners` set made for one sidebar's storage key; the Board thread's `SessionThreadTabs` in `web/components/board/page.tsx` uses it, `sessionOverviewTab`, and `sessionWorkTabs` with its own `DetailsSidebarFrame`, whose `trailing` slot holds the thread's close button.
  `ArtifactsPanel` draws a toolbar as the Browser's, `min-h-9` with ghost `icon-compact` buttons: the shown artifact's kind icon and title, a `DropdownMenu` picking another once there are two, the **Preview** and **Source** switch on `SegmentedTabs`, and **Copy**, **Download**, and **Open in browser**; the version full-bleed below; and a version bar with older and newer arrows around a **Version N of M** menu, the note, and the kind, size, and save time or **Go to latest**, under a `@container/artifacts` that puts the title on its own row below 24rem and keeps only icons below 30rem; it reads whether the right sidebar is open from `SidebarOpen` in `sidebar-panel.tsx`.
  `ArtifactView` in `artifact-view.tsx` draws a version by its kind's row of `ARTIFACT_KIND`: HTML in an iframe sandboxed without `allow-same-origin`, whose clicked inline image it opens in `ImageViewer` when the frame posts `parseArtifactImages`' message, SVG as an `<img>` that opens there too, Markdown through `MessageMarkdown` in a centered reading column that `.artifact-document` in `web/globals.css` sets as a document, and any kind's source through `CodeText` from `file-text.tsx`; while the version loads, or once it failed, it shows `LoadNote` from `sheet-details.tsx`.
  `ArtifactCard` in `artifact-card.tsx` is a save's tile in the transcript, a button with the kind's icon, the title, and its kind, version, and note, reading **Open** on hover and **Showing** while the tab shows that version.
  `artifacts-panel.test.tsx` covers the version bar's arrows at either end, **Go to latest**, and a single version; `artifact-card.test.tsx` covers the card's version line and **Showing** state.
  `BrowserPanel` holds the Browser's tabs, UI SDK tabs that `BrowserTabStrip` draws as a web browser's: the session's **App** and one per page of the last **Review visuals** click, each a `BrowserPage` kept mounted while hidden; only the **App** tab saves the address it opens on next time.
  A listed page that the shell's `openDashboard` opens in an app of its own, another omp-agents server's, gets no tab.
  The default is **PRs**; a stored choice of the removed Todos, Files, Media, or Processes tab falls back to it.
  Each pull request shows through `PullRequestDetails` from `web/components/pull-requests/pr-page.tsx`, whose `session` lists the others under the **Stack** and whose `onPick` shows another pull request of the stack or the session in place of changing the address.
- `web/components/transcript-minimap.tsx`: `TranscriptMinimap`, the rail of one line per turn on a transcript's left edge, after Notra's Chat Minimap, on `HoverCard` and `Tooltip` from `web/components/ui/`; it shows from two turns on, where its `MessageScroller`'s container query leaves room beside the messages, scrolls its own transcript's viewport to a turn's prompt, and lights the turn whose prompt last crossed the reading line.
- `web/components/find-bar.tsx`: `FindBar`, the find bar that Cmd+F opens over one part of the page: `Transcript` mounts it in its `MessageScroller`, enabled in the pane `PaneFocused` marks, which `ViewConversation` in `pane.tsx` provides, and `PullRequestDetailContent` on its tab bar where its host passes `findable`, the Pull requests page and its docked details.
  It finds the text nodes its root shows with `findMatches` from `web/find-matches.ts`, so a match may span a code block's tokens, paints them with the CSS Custom Highlight API under the `::highlight()` rules in `web/globals.css`, finds them again on each change a `MutationObserver` sees, and scrolls only the nearest scroller of the current match.
- `web/components/session-overview.tsx`: `SessionOverview`, the right sidebar's **Overview** tab, a stack of sections that each show only with items: the **Jobs** section of `overview-jobs.tsx`, the **Subagents** section of `overview-subagents.tsx`, then the sections of `overview-changes.tsx`; with none it shows `DetailsEmpty`'s **Nothing yet** once `useChanges` reports all three lists loaded, and nothing before.
  `SessionDetails` hands it the view's `SubagentLinksValue` from `useSubagentLinks`, `null` in a past session, and the `ChangesSession` built from the focused session's id and its roster row, last roster row, or past entry, whose directory outlives an ended session.
- `web/components/overview-changes.tsx`: `useChanges`, the view's changed files, images, and sources, leaving out the session's own pull requests, and `ChangesSections`, the **Files**, **Images**, and **Sources** sections with **Review** and the dialogs a file opens; the folded sections stay under the `omp-agents.changes-card-closed` key from before the sections moved into the sidebar.
- `web/components/overview-section.tsx`: `OverviewSection`, the filled folding header, an `h3` holding its title, count, and chevron, and the body each of the tab's sections shares.
- `web/components/overview-jobs.tsx`: `JobsSection`, the **Jobs** section, one row per background job of the session from `JobsContext` in `web/jobs-context.ts`, each a button that unfolds its last lines, with the progress `jobProgress` in `src/shared/jobs.ts` reads from them; its fold stays under `omp-agents.overview-jobs-closed`; see [Background jobs](../architecture/background-jobs.md).
- `web/components/overview-subagents.tsx`: `SubagentsSection`, the **Subagents** section, one row per subagent from `subagentTree` in `web/overview-subagents-model.ts`, indented by depth, each a two-line link to the subagent's view, its id and activity over `SubagentMeta`, its model, type, and `runTime`, and the stop button of a running one; its fold stays under `omp-agents.todos-card-subagents-closed`.
  Above the rows, each arena from `arenaGroups` shows as a box with its task, its runners as cards side by side, each a link with its seat letter, status, activity, `SubagentMeta`, and after the pick a **Base**, **Graft**, or **Not used** badge, and its judge as a row under them; the arenas come from the session row's `arenas`.
  A subagent's view lists only its own descendants.
- `web/components/subagent-links.tsx`: `useSubagentLinks`, which builds a live view's `SubagentLinksValue`, the session's subagents, the page's open, and the cancel, `null` in a past session, from the view and its roster row for the **Overview** tab and the details sidebar's **+** menu; and `CancelAgentButton`, the stop button after a running subagent's link in **Overview**.
- `web/components/prompt-history.tsx`: **Chat history**, after Kobra's Chat History: `PromptHistoryButton`, the live composer's button from two prompts on, which selects only the view's prompt count, and `PromptHistory`, which `Transcript` mounts in its `MessageScroller` and draws, while a keyed store by the view's hash holds it open, as a blurred layer with the turns of the transcript model's `outline` as one column of prompt bubbles; prompts in view slide from their measured place in the transcript, and a pick scrolls the viewport with the minimap's `scrollToMessage` and outlines the bubble.
- `web/components/changes/`: the session's changes dialog, `session-changes-dialog.tsx`, in its frame, `explorer-dialog.tsx`, with its explorer and editor, `changes-explorer.tsx`, the explorer's tree, `file-tree.tsx`, the Diff view's list of every file's diff, read as each nears the view, `diff-stack.tsx`, and one file's diff and File views, `code-view.tsx`.
  `use-file-cursor.ts` holds the file an explorer marks, which ↓ and ↑ step through; the explorer and a pull request's **Code** tab, `web/components/pull-requests/pr-details/code-files.tsx`, each lay out `FileTree` and `DiffStack` around it.
  `web/components/line-counts.tsx` draws the lines added and removed, `+12 −3`, that the changes dialog and the **Overview** tab share.
  `web/diff-options.ts` holds shared diff preferences and the whitespace-only replacement transform.
  The changes dialog's explorer orders the files as its tree does; the **Code** tab keeps the server's reading order and puts the tree at the right.
  Each of them holds which files `DiffStack` shows folded, through `useCollapsedFiles` there, so the **Code** tab folds them all at once or folds one marked viewed.
  `diff-review.ts` is the context a page reads its diffs through: the layout, wrapping, and whitespace it chose, the box it shows under picked lines, which the Code tab fills with `web/components/pull-requests/pr-details/diff-controls.tsx`, and the end of each file's header, which it fills with the Viewed checkbox from `viewed-files.tsx` beside it; the changes dialog takes the defaults and picks no lines.
