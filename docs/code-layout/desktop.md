# Desktop

`desktop/` holds the desktop shell; see [Desktop shell](../architecture/desktop-shell.md).
`desktop/main.ts` is its main process, with `desktop/shell-env.ts` and `desktop/updates.ts` for the packaged app, and `bun run desktop` at the root installs the package and starts it from the checkout through `desktop/launch.ts`; `scripts/build-desktop-artifact.ts` packages it (see [Packaging and releases](../architecture/desktop-shell.md#packaging-and-releases)).
`desktop/preload.ts` is the window's preload, which gives the page the `DesktopBridge`, and `desktop/attention.ts` takes what the page sends through it: the Dock badge's count, the session notifications, whose click shows the window on the session, and the sound the page plays alone.
The bridge's guarded no-argument `installStarterKit` shares the menu's fixed non-forced installer and returns its inline result to Get started.
`main.ts` turns what `desktop/server-supervisor.ts` reports into the window's page, the missing-omp child exit into a server-free install notice among them; `shell-env.ts` refreshes only executable discovery on Retry, leaving initialized data paths alone.
`desktop/server-supervisor.ts` holds `ServerSupervisor`, free of Electron: it spawns the server, waits for its listening line, rolls the checkout back through `src/server/update-journal.ts` when an update's build did not start, and restarts a server that stopped on the waits of `afterLoss` in `desktop/restart-policy.ts`; `desktop/server-supervisor.test.ts`, which the root `bun test` and typecheck run, covers the restarts, giving up, a first start that fails, and a rollback in a scratch checkout.
`desktop/preview-preload.ts` is the preload of the Browser's `<webview>`, which runs `desktop/preview-pick.ts`, bundled to `dist/preview-pick.txt` and imported as text (`desktop/text-modules.d.ts`), in the app, where it draws the Browser's Select and reads the selected elements, and hands what the app reports to the page; see [Desktop shell](../architecture/desktop-shell.md).
`desktop/bippy-core.d.ts` gives `bippy/core`, which `desktop/preview-pick.ts` names components with, the types bippy 0.6.1 ships under another file's name.
`desktop/browser-guests.ts` holds the rules of the Browser's `<webview>` guests: what each gets when it attaches, where its navigations and new windows go, the ports its session and other servers listen on, the **Screen size** each emulates, and the captures the page asks for.
On macOS the launcher clones `node_modules/electron/dist/Electron.app` to `desktop/dist/omp agents.app`, sets its `CFBundleName`, `CFBundleDisplayName`, and `CFBundleIdentifier`, gives it an `.icns` that it renders from `icon.png` with `sips` and `iconutil`, signs it ad hoc, and runs that copy, because the Dock, the menu bar, and Cmd+Tab read an app's name and icon from its bundle.
It rebuilds the copy when Electron's version or `icon.png` changes.
`desktop/icon.svg` is the app icon, the logo mark on a macOS-style tile, and `desktop/icon.png` is that SVG rendered at 1024 px, because Electron reads no SVG; render it again after you change the SVG.
The page's favicon, `web/favicon.svg`, is the bare mark.
