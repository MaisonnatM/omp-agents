# Server: git, worktrees, pull requests, merges, and sync

- `src/pull-requests.ts`: maps each workspace to its GitHub repository, reads the pull request list with one `gh api graphql` call per repository, plus one for open review threads it has not seen, and reads one pull request's details with one more.
  `branchPullRequest` asks one `gh api` REST call, outside GitHub's search and the GraphQL budget, for the newest open or merged pull request a branch heads, for `src/session-facts.ts`.
  `mergedPullRequests` asks one `gh api graphql` call for the newest pull request from each of a repository's branches, with one alias per branch, and keeps the merged ones with their merge time, for `src/worktrees.ts`.
  `loadPullRequestTitle` reads only a linked PR's title through a separate 30-second cache, without loading its details.
  `src/github.ts`'s `repoOf` keeps each workspace's repository, or its lack of one, for ten minutes in a `createCache` from `src/cache.ts`, and runs at most eight `git remote` lookups at once through a `limit` gate from `src/map-limit.ts`.
  `ghRest`, `ghGraphql`, and their write helpers run through the installed kit's `GitHubAccess`, which pauses only the exhausted REST or GraphQL budget until its reset, across processes; the `createCache` layers above them are the only answer caches.
  Quota failures remain failures, not authentication diagnoses or stale successful answers.
  `runJson` in `src/proc.ts` rejects a non-zero exit with the kit's `CommandError` even when stdout parses, keeping the parsed answer; `answered` in `src/github.ts` returns that answer, so GitHub's refusals and GraphQL's partial `data` still reach the caller that classifies them, such as a batched merge read that keeps the pull requests GitHub did answer.
  On top of that, the list's query, the stack's, and the merge cleanup's state reads go through `ghPolledGraphql` in `src/github.ts`, which asks `githubQuota` first; `src/github-quota.ts` holds `GithubQuota`, which keeps them from spending the last `GRAPHQL_RESERVE` GraphQL points, until the quota resets, and `GithubQuotaPaused`, the error that names when.
  A row's `conflicts` is true when GraphQL's `mergeable` is `CONFLICTING`.
  The list leaves out a pull request whose own state says closed, which the open searches still return for up to a minute after a close, since GitHub's search index lags it.
  A row and the details read `checks`, `conflicts`, and `unresolved` from the same GraphQL fields, so `readyToMerge` in `src/shared/moves.ts` takes either; the details count `unresolved` from the threads they keep, so their counts and threads agree.
  `unresolved.bots` counts the open threads whose first comment a bot wrote, by `isBotAuthor` in `src/shared/github.ts`, the same test as the details' **Bot comments** filter; the details count it through `unresolvedOf`.
  The list's query asks each thread only its `id` and `isResolved`, and `readThreadStarters` reads the first comment's author of each open thread it has not seen, through `nodes(ids:)`, keeping each repository's answers for the threads still open, since a thread's starter never changes.
  The details also read the last 100 commits with the pull requests GitHub links each to, and keep a commit linked to none or to this one, since a branch that merged its trunk lists the trunk's commits too.
- `src/git.ts`: the git checkout of a directory, the worktree a directory is in (`worktreeAt`), the branch a worktree had checked out at a given time (`headHistory`, `branchAt`), and the worktree a new session's branch runs in.
  `CachedCheckouts` answers `worktreeAt`, `headHistory`, and `defaultBranchOf` again from memory while the files git read for each keep their inode, modification time, and size.
  It also holds the git helpers that `src/worktrees.ts` shares: `git`, `canonical`, `commonDir`, `worktreesOf`, which parses `git worktree list --porcelain -z`, and `holderOf`, the worktree that has a branch checked out, which the pull request checkout and rebase use too.
- `src/worktrees.ts`: the worktree inventory and the checks before a checkout is removed; `Worktrees.start` and `Worktrees.remove` order starts against removals; `removeCheckout` removes the linked worktree a directory is in, or returns `null` for a main checkout or a directory outside git, waiting up to 15 seconds for a session that just ended to leave it: it polls only which live sessions occupy the checkout, then runs the full preview once.
  `releaseBranch` removes the linked worktree that has a branch checked out through `removeCheckout` without that wait, and answers a `BranchRelease` from `src/shared/git.ts`, for `PUT /api/worktree/release`.
  `deleteMergedBranch` deletes a local branch only while its commit is the one its pull request merged, or one that commit contains, and no worktree has it checked out, for the cleanup after a merge.
  `inUse` names the known directories of live sessions, resident subagents, and the server, which keep an isolation sandbox, and `beneath` tells whether one holds another.
  The inventory and the snapshot of what uses the checkouts resolve each distinct directory once, and run those realpaths and the per-directory and per-repository git probes `PROBE_PARALLEL` (16) at a time.
  The inventory then reads every repository's checkouts from one queue, four at a time, with one `git rev-parse` for their identity, and `previewAll` previews several targets from one snapshot of what uses them, four at a time; `src/map-limit.ts` holds `mapLimit`, the ordered, bounded `Promise.all` they share, and `limit`, a gate that bounds tasks arriving one by one.
  A preview reports a path that git no longer lists as a worktree with the `unregistered` blocker, which `Worktrees` tells apart from other failures by its `UnregisteredWorktree` error class.
  The inventory marks each linked checkout's `merged`: `git merge-base --is-ancestor` against `refs/remotes/origin/HEAD` for each distinct commit, then one `mergedPullRequests` call per repository, through the `WorktreesEnv` seam that tests fake, for the branches the default branch lacks.
  A merged pull request counts only when the branch's last commit is no newer than the merge, read with one `git log --no-walk` call.
  `previewAll(targets, true)`, for **Remove merged**, runs the same check and adds the `unmerged` blocker to each target it cannot show merged; removal needs no second check, since the confirmation pins the branch and commit.
- `src/server/worktree-occupants.ts`: `WorktreeOccupants`, the resident sessions and subagents whose directories protect checkouts from removal.
  It reads each live child's native default directory through the uncached `readSessionCwd` and all declared Bash directories through an incremental `SessionFactsScan`.
  Changed transcripts are streamed through a prefix fingerprint before an append is trusted; unchanged files reuse their folded records and fingerprint.
  It retains known paths during transcript failures, roster reconnects, and a surviving child's parent session switch, and supplies unresolved repository scopes until complete evidence returns.
  `Worktrees` owns canonical paths, Git identity, and containment. The collector owns residency and its per-live-transcript cache.
- `src/local-file.ts`: finds a file that agent text names by absolute path, by the real path's extension and outside the sign-in and config directories in `DENIED_DIRS`: `readTextFile` reads a text file for `GET /api/file`, within the size and encoding that route allows, and `findMediaFile` an image or video for `GET /api/media`.
  `src/worktrees-shared.ts` holds the shapes the page and the routes share.
- `src/changes.ts`: the session changes dialog's reads for `GET /api/changes` and `GET /api/changes/file`, a session's checkout diff merged with its own changed files, the last scan of each place kept for three seconds so that reading a file does not list every change again, and each session transcript folded into its changed files once, by the lines it gained since; `src/shared/changes.ts` holds the shapes the page shares, `parseFullDiff`, which numbers the rows of a whole-file diff, and `patchRows`, which fills GitHub's patch out to the whole file.
- `src/pull-request-files.ts`: the Code tab's REST file and blob reads, optional commit scope, and paginated GraphQL viewed-state read.
  `src/pull-request-order.ts` orders the list: sources after the files they import, then tests in their sources' order, then generated files.
  `src/pull-request-stack.ts` reads the stack for `GET /api/pull-request/stack`.
  `src/pull-request-edit.ts` saves titles, descriptions, labels, review requests, states, branch updates, and conversation changes for `PUT /api/pull-request`, and viewed files for `PUT /api/pull-request/viewed`.
  It also lists picker choices for `GET /api/pull-request/options`, the reviewers with their profile names through `parseAssigneesAnswer`, and appends images with `attachToPullRequest`.
  Description changes use the shared checked transaction in `templates/omp/agent/extensions/github/description.ts`, preserving a private original and refusing observed concurrent changes before the REST write.
  `src/pull-request-checkout.ts` checks out a pull request for `PUT /api/pull-request/checkout`: with `gh pr checkout` in a checkout, or on its head branch in a worktree with a new session that the route's starter opens there.
  `src/pull-request-rebase.ts` rebases a pull request's branch onto its base for `PUT /api/pull-request/rebase`, in the worktree that has the branch or a temporary one, and force-pushes it with a lease through the repository's pre-push hook, one repository at a time.
  Both read the pull request's head and base branches through `headOf` in `src/pull-request-head.ts`, and refuse a workspace of another repository through `assertWorkspaceOf` there.
  `src/pull-request-merge.ts` holds `GITHUB_MERGES`, the merge and its steps, including merge or rebase branch updates, and the status reads.
  `src/pull-requests.ts` adds `behindBy` with one REST base-to-head comparison per detail read.
  `src/pull-request-review.ts` holds a review draft's side of GitHub: `readReviewTarget`, the head and the lines each file's diff shows, the viewer's login, the reviews and their comments a retry compares, and `postReview`, one `POST` of the review through `ghRestPost` in `src/github.ts`.
- `src/github-media.ts`: `GET /api/github-media`, authenticated reads of allowlisted GitHub images and videos with redirect validation, a streamed size cap, and a bounded private cache.
- `src/favicon.ts`: `GET /api/favicon`, the icons of the sites the Todos card's Sources section lists, read from public HTTPS hosts only, with a day-long private cache that keeps misses too.
- `src/server/merge-queue.ts`: `MergeQueue`, every merge the dashboard makes, kept in `merges.json` and stepped only by the server that holds the owner lock, `nextStep`, which picks a merge's next step from where its pull request stands, and `stackOrder`, which orders a stack of one repository bottom first; `src/shared/merge-queue.ts` holds `QueuedMerge`, `MergeQueueChange`, `MergeQueueAnswer`, and `queuedMergeOf`, which the page shares; see [Merges, and the cleanup after one](../architecture/merges-and-the-cleanup-after-one.md).
- `src/server/review-drafts.ts`: `ReviewDrafts`, the **Review** session's `save_review_draft` host tool, bound to its pull request through `join` and the `Reviewer`s it keeps, and the preview and post of a draft, which takes a matching review already on GitHub instead of posting twice; `src/server/review-drafts-file.ts` keeps the drafts and reviewers in `review-drafts.json` beside the access token; `src/shared/review-drafts.ts` holds `ReviewDraft`, `ReviewFinding`, `ReviewDraftEdit`, `applyReviewDraft`, `reviewPayload`, which builds the review from the accepted findings and the diff's lines, and `postRefusal`, which the page shares; see [Review drafts](../architecture/review-drafts.md).
  `canApprove` in `src/shared/review-drafts.ts` decides where the composer, the details header, and a row's menu offer an approval.
- `src/server/merge-cleanup.ts`: `MergeCleanup`, which marks the live sessions linked to a pull request that merged while it watched, and ends each once it is idle and not held for a continue with every pull request merged or closed, with its worktree and its merged branch, trying a failed or refused end again at the next look.
- `src/server/isolation-sweep.ts`: `IsolationSweep`, which once a day, on the owner's minute tick, removes each of omp's isolation sandboxes whose omp exited and whose checkout is clean, unlocked, and unused; `src/omp/isolation.ts` supplies omp's directory, its owner marker and liveness check, and its teardown of a retained mount; see [Isolation sandboxes](../architecture/routines.md#isolation-sandboxes).
- `src/source-control.ts`: Settings › Source control on the server: `gh`'s and `gt`'s sign-in, the automatic pull setting and the cleanup after a merge in `source-control.json`, and `pullDefaultBranch`; see [HTTP API](../architecture/http-api.md).
  `src/shared/source-control.ts` holds the shapes the page shares, the merge methods and their labels, `applySourceControl`, and `startingMethod`, which picks the method the merge button starts with.
- `src/settings-sync.ts`: Settings › Sync on the server: `SettingsSync` runs one sync at a time against `SyncRepo`, `readLocal` and `applyLocal` read and write this machine's side, `planSync`, `mergeFile`, and `mergeJson` merge three ways, lists entry by entry, `portableText`, `portablePath`, and `localPath` carry home paths as `~`, and `syncStores` builds the `SyncStore` of each dashboard store, `sourceControlStore` for `SourceControl`'s settings and one over each `ReducerFile` for the notes, todos, preferences, workspaces, and hidden calendars; see [Settings sync](../architecture/settings-sync.md).
  `src/sync-repo.ts` holds `SyncRepo`, the git commands on the bare repository under the data directory, run without prompts; `src/shared/settings-sync.ts` holds the registry, `SYNC_ITEMS` and `NEVER_SYNCED`, the shapes the page shares, and `parseSyncSettings`.
- `src/server/self-update.ts`: **Update dashboard**: `SelfUpdate` reads the build the server runs at startup, counts origin's new commits for the bell, reads `CHANGELOG.md` on the running build and on origin for What's new, and fast-forwards the checkout, installs when `bun.lock` changed, and has the server restart; `fastForward` refuses rather than stash, reset, or merge; see [Updating the dashboard](../architecture/updating-the-dashboard.md).
  `src/shared/dashboard-update.ts` holds what `GET` and `PUT /api/dashboard/update` answer.
